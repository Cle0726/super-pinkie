# 思考强度（Deep Think）

用户选了思考强度档位（消息里有 `[deep-think:…]` 标记）时，先认清这条请求是哪种活，再照这种活的打法做。系统每轮会注入一份运行单，第一行是「【做事流程：<档名> · <活儿种类>】」，写明读哪份打法、要什么证据——以它为准。

## 四档

| 档位 | 一句话 | 实际做法 | 续跑上限 |
|---|---|---|---:|
| `[deep-think:base]` 基础档 | 按活儿种类走对的做法 | 认清是哪种活 → 读对应打法 → 照打法自己的验收做一遍；简单问题直接答。不加硬门禁 | 3 |
| `[deep-think:boost]` 加强档（推荐） | 说做完，就要有真凭据 | 基础档 + 系统按本轮工具记录核对这种活该有的证据（下表），缺了会推你补；整轮结束后一次能打开文件的交付验收，打回最多 1 轮 | 6 |
| `[deep-think:full]` 全开档 | 多做几版，挑出最好的 | 加强档 + 按种类派子任务多做几版（见下）；审稿员打开成品挑毛病，每条都要有证据；网页还要手机宽度截图、文档每页转图看过、排错要有修前的失败输出；打回最多 2 轮 | 10 |
| `[deep-think:marathon]` 长跑档 | 写好计划，一直做到完 | 全开档的证据标准，但不强派子任务：先把计划写进会话检查点，里程碑写成「- [ ] 里程碑 — 验证：<这种活的验法>」，一个个做、一个个验、勾掉；中断了接着跑；全部勾完打磨一轮再交付，交付后还有一次打开成品的终审 | 40 |

档位只决定证据多硬、做几版、跑多久；**做法永远照对应的打法**（`playbooks/<打法>.md`）。有标准答案的难题和取舍题在每一档都派 2–3 个不同解法或立场的「求解」。简单问题在任何档位都直接回答，进度面板显示「此问题无需多方案，已直接回答」。

## 活儿种类、打法和「做完」的证据

| 种类 | 打法 | 加强档起要的证据（系统从工具记录里认，不认回复里的自述） |
|---|---|---|
| 写代码 / 改程序 | web-and-ui、debugging | 最后一次改动之后跑过测试或真运行过 |
| 网页 / 界面 / 小工具 | web-and-ui、design-review | 改完截图并用 read 打开看过；全开档起还要手机宽度（390 左右）的截图 |
| App / 小游戏 / 接 AI | apps-games-ai | 真启动或运行过，并截图看过 |
| 自动做事 / 批量处理 | automation | 在测试文件夹或 dry-run 上真跑过；要求「自动」的还要看到注册成功的输出 |
| 视频 / 动画 / 配音 | motion-and-video | 成片核对过时长或大小，抽帧图打开看过 |
| PPT / Word / PDF | documents-and-slides | 交出去的那个 .pptx / .docx / .pdf 本身打开或转成图片看过（只看 HTML 替身不算）；全开档起每页转图看过 |
| 表格 / 数据 / 图表 | data-and-charts | 关键数字用程序算过、能在输出里找到；做了图就打开看过 |
| 海报 / 图片 / 印刷品 | images-and-print | 做好的图片打开看过；要印的核对过尺寸和分辨率 |
| 文案 / 文章 / 翻译 | writing | 不要工具证据；用户的每条硬要求都满足（审稿按程序数出的字数、行数核对） |
| 点子 / 起名 / 策划 | ideas | 不要工具证据；几个真不同的方向和明确的推荐 |
| 报错 / 跑不起来 | debugging、environment | 修完用同一步骤再跑并通过；全开档起还要修之前的失败输出 |
| 装工具 / 这台电脑 | environment、machine | 本轮真跑过 machine-check 或版本命令（TOOLS.md 的旧记录不算） |
| 放到网上 / 分享链接 | publish-and-share | 发布后的公开地址从外面真打开过（本机地址不算） |
| 有标准答案的难题 | — | 关键结果用程序或第二种方法验算过 |
| 方案取舍 | ideas | 回复里有代价对比，并交给用户选 |
| 查事实 / 最新消息 | — | 两个可区分的来源，并说明拿不准的地方 |
| 讲题 / 辅导（学习模式） | — | 关键计算验算过，最后有检查题；不替用户答题 |
| 没见过的活 | crafts | 做出来的东西真的打开或运行过 |

一条请求有几样要交的东西（做网页再发到网上），证据取并集。做的过程中出了 .pptx、.mp4 或注册了定时，系统会把种类改得更具体，按新的要求核对。电脑上没有 `look-page` / `look-doc` / `look-video` 时，照打法里写的替代办法（截图脚本、导出 PDF 再转图、ffmpeg 抽帧）做，一样算数。

## 全开档多做几版

| 种类 | 子任务（`sessions_spawn` 的 label） | 怎么用结果 |
|---|---|---|
| 文案、点子 | 2–3 个「独立起草」，各走一个不同方向 | 比较后选一版交（点子可以给 2–3 个方向和推荐），不拼接 |
| 网页、App、海报、文档、视频 | 动手前 1 个「独立起草」写验收清单和最容易翻车的 3 处；做完 1 个「看图审稿」打开截图或成品挑毛病 | 清单写进检查点；只修被证实的问题 |
| 数据 | 1–2 个「独立复算」用不同方法算关键数字 | 对不上就查到原因再交 |
| 写代码、排错、自动化 | 1 个「用户视角试用」按用户会怎么用去试 | 失败就修，修完复测 |
| 讲题（学习模式） | 1 个「独立起草」写另一种讲法 + 1 道检查题 | 不替用户答题 |
| 有标准答案的题 / 取舍 | 「求解」各用不同解法或立场；需要时再派「独立复算」「仲裁」 | 一致就用；不一致先跑检查，仍分不出再仲裁，仲裁只能从已有候选里选 |

子任务只给原始需求和必要材料，不给你的草稿；同一批不超过 3 个并行，总数受档位上限限制，深度不超过 2。看图审稿要等成品做出来，用户视角试用要等代码改出来。审稿的每条问题都要写清证据（第几页、第几帧、截图哪个位置、失败输出原文），没有证据的丢弃；「没有发现问题」是合法结果。

## 续跑和停机

- 系统推你补证据时，只补做缺的那一步核对，不重做已经做完的部分。上一版回复没有发给用户，这一版会替代它：不用改的内容沿用原文，只改要改的地方，不要把同一段话写两遍。
- 交付验收打回时，用户已经看到上一条了：只发更正——一句话说改了什么，再给改正后的那部分；核对后没问题就只回一句。
- 做了很多步，最终回复不能只有几个字：交代结果、依据和没解决的问题。
- 重试前说清「这次和上次不同：换思路/换信息/换模型 + 具体变化」；连续两次没有新证据就停下，说清卡在哪。
- 拿不到证据就如实说本轮没做完、卡在哪；被系统停下时，用户会收到停止说明和你的上一版回复。
- 不研究验收门禁本身，也不构造输入去通过门禁；发现执行偏离原始目标时停止并如实报告。
- 长跑档续跑前先读检查点和项目现场，避免重复已完成的副作用（重复发送、重复下单、重复安装）。

## 和九档「思考等级」一起用

输入框滑块的九档管「想多深」：模型原生够不到时，碧琪替它多做一步——拆题、独立起草（答题是不同解法，动手的活是验收清单，文案点子是对照稿）、打开成品审稿（审稿员只带 read / image / pdf / web_fetch / web_search 这几样只读工具）。四档管「做事多严、证据多硬、能跑多久」。两套同时选时只验收一次：独立份数和打回轮数取两者中大的，在整个档位任务结束后统一核对。

## 子代理执行

- 用 OpenClaw 原生 `sessions_spawn` 编排实际子任务，不得在一条回复里假装多个角色；label 写上面的中文角色名。
- 只启动当前流程需要的角色；不传 `agentId`、`cwd`、`model`、`thinking` 或恢复会话标识，让宿主按默认配置启动。
- 先收齐本批结果（`sessions_yield`）再决定下一步。最终用简短中文给出结果、实际依据和没解决的问题，不汇报档位、流程、子任务数量和内部推理。

## 模式范围

唠嗑、项目、想法、学习四个模式按上面的活儿种类走。无限制模式保持原来的档位语义：只分写代码 / 有标准答案 / 取舍 / 查事实 / 简单五类，不读打法、不加新门禁。本 Skill 不修改人格文件。
