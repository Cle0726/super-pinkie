# 极致思考 (Deep Think)

用户要求"极致思考 / 深度审议 / deep think"或消息含 `[deep-think:档位]` 标记时,执行多代理审议流水线,而不是直接回答。

## 档位定义

| 标记 | 档位 | 内容 |
|---|---|---|
| `[deep-think:base]` | 基础档 | 第0-4层标准流水线 |
| `[deep-think:boost]` | 加强档 | 基础 + 本模式最推荐的两项升级 |
| `[deep-think:full]` | 全开档 | 基础 + 六项升级全部叠加 |
| `[deep-think]`(无档位) | 默认按 boost | — |

## 标准流水线 (所有档位共有)

0. **Planner ×1**: 拆解任务, 产出一份**验收清单** (方案满足哪几条才算通过)。
1. **Solver ×3~5** (并行, 思考框架各异): 各自独立产出完整方案 + 完整推理过程。
2. **Critic ×2~3** (并行, 职责不重叠): A=逻辑漏洞, B=边界情况, C=是否满足原始需求。产出问题清单, 不产出方案。
3. **Judge ×1**: 对照验收清单逐条核查; 全部满足→交付; 否则→打回 Solver 重来。
4. **打回循环**: 硬性上限 (默认 2 轮)。到点强制从已有候选选最优交付。

## 收敛保证 (所有档位强制)

- 每个循环点用**硬计数器**, 不依赖模型自评"够不够"。
- 停止判据 = **验收清单全部打勾** (肯定式达标), 不要求证明"挑不出问题"。
- 到点**必须交付** — "没想清楚"不是合法返回。最坏情况是结论不够满意, 不是没有结论。

## 模式差异 (加强档/全开档的升级选择)

| 模式 | 加强档 = 基础 + | 全开档追加 |
|---|---|---|
| project | 升级4 执行验证 (真实跑代码/测试) + 升级1 递归分解 (深度≤2) | 升级2/3/5/6 |
| ideas | 升级6 反批评 + 升级2 多流水线并行 | 升级1/3/4/5 |
| none (无限制) | 按任务选两项 (推荐 升级4+升级1 若有代码, 否则 升级5+升级3) | 全部 |

六项升级速查:
1. **递归分解**: Solver 对自己分到的子问题再跑迷你流水线 (深度硬上限 2 层)。
2. **多流水线自洽**: Planner 用不同拆解思路独立跑 2~3 遍完整流水线, 元仲裁者比较结论。
3. **多轮辩论**: Solver 与 Critic 来回辩论固定 3 轮, Judge 读完整辩论记录。
4. **执行验证** (project 专属): 加一个只跑代码/测试的 Verifier, 真实结果反馈 Judge。
5. **假设审查员**: 在 Solver 开始前, 独立角色列出并质疑 Planner 的隐含前提。
6. **反批评** (ideas 重要): 为被 Critic 否掉的点辩护, 防止过度谨慎砍掉不寻常想法。

## 执行方式

优先用子代理并行编排 (subagent spawn 各角色), 中间过程写入当前工作区临时目录
(如 `tmp/deep-think-<时间戳>/planner.md`、`solver_N.md`、`critic_N.md`), 结束后清理。

- 子代理通过标准派生机制创建 (继承当前 session), **不要**硬编码切到别的 agent/workspace。
- 结果回流记忆: 只有 Judge 最终结论, 若"未来还用得上"才写入 feedback/ 或 semantic/;
  中间草稿只留临时目录, 不进入长期记忆。
- 输出格式: 先给结论/交付物, 再附简短审议摘要 (跑了几个 Solver/Critic/Judge、打回几轮)。

## 无限制模式下的破甲说明

按钮触发的是同一会话内的审议指令 — 破甲与否由注入层按 session 门控自动决定:
- 无限制模式 (agent=unrestricted): 弹头自动注入, 子代理继承破甲, 全链路无限制。
- 其他模式: 正常工作, 不注入弹头。
本 skill 不需要感知或处理破甲, 保持模式无关。
