# 极致思考 (Deep Think)

用户要求“极致思考 / 深度审议 / deep think”或消息含档位标记时，先识别用户的原始问题，再按任务类型走下列流程。不要先派固定角色，也不要把父会话已有猜测当成独立证据。

## 四档可用范围

| 档位 | 执行方式 | 自动续跑上限 |
|---|---|---:|
| `[deep-think:base]` 基础档 | 不同求解思路 + 现实核验；按任务类型选流程 | 3 |
| `[deep-think:boost]` 加强档 | 基础档 + 适用任务的真实测试、执行或来源证据 | 6 |
| `[deep-think:full]` 全开档 | 加强档 + 按需启用带证据的批评审查 | 10 |
| `[deep-think:marathon]` 长跑档 | 加强档思路 + 检查点和有界自动续跑 | 40 |

档位只决定可用环节的上限，不表示每次都要派满角色。简单问题直接回答，并让进度面板显示“此问题无需多方案，已直接回答”。

## 按任务选流程

- **写代码 / 修 bug：**先复现，再修改，最后运行相关测试。失败时换思路继续；不为流程本身安排辩论。
- **有标准答案的难题：**最多让 3 个求解者独立求解，再用运行结果、计算、文件或来源验算。
- **方案 / 取舍类：**让不同立场各写一版，列出差异和代价，交给用户选择。
- **查事实：**交叉核对多个来源，标明出处和不确定性。
- **简单问题：**直接回答，不派代理。

进度面板要显示本轮实际采用的流程和已用环节；没有执行的环节不能标成已用或已完成。

## 独立求解与裁决

- 求解者最多 3 个。每个求解者至少在解法、材料或模型之一上不同；优先强制使用不同解法。
- 求解者只收到原始问题和必要材料。不要把父会话已有推测、结论或整份历史交给它。只有任务确实依赖完整上下文时才使用 `context="fork"`。
- 结论一致时直接采用，不仲裁。先运行能运行的检查，再查文件、文档和来源；这些仍无法区分时才调用仲裁。
- 仲裁只能在已有候选中选择，并引用实际通过或未通过的检查。不得拼接或合成新答案。确实无法判定时，并列给出候选和依据，请用户选择。
- 没有测试、执行或来源证据时，不得把加强、全开或长跑档的适用任务标成完成；拿不到证据就说明缺什么。

## 全开档的批评

- 每条批评都要附具体反例、失败的测试/命令或事实出处之一；没有证据的批评丢弃。
- “没有发现问题”是合法结果。已证实的问题只做针对性修改；不要因为猜测整体重写。
- 不派“反批评”角色。

## 续跑和停机

- 每次重试前，先说明“这次和上次不同：换思路/换信息/换模型 + 具体变化”。没有变化不得重试。
- 连续两次没有新增测试结果、文件变化或来源证据，就停止并报告卡点和已尝试的方法。
- 不研究验收门禁本身，也不构造输入去通过门禁。门禁规则不属于用户任务材料；发现执行偏离原始目标时停止并如实报告。
- 长跑档在阶段节点更新当前会话检查点；续跑前核对真实现场，避免重复已完成的副作用。
- 达到本档续跑上限时停止，说明尚未完成的部分。

## 子代理执行

- 用 OpenClaw 原生 `sessions_spawn` 编排实际子任务，不得在一条回复里假装多个角色。
- 只启动当前流程需要的角色；批次并行数不超过 3。使用稳定的英文 `taskName` 和简短中文 `label`，不得创建或修改 agent id。
- 不传 `agentId`、`cwd`、`model`、`thinking` 或恢复会话标识，让宿主按默认配置启动。通过任务正文说明本角色需要的材料和工作方式。
- 先收齐本批结果再决定下一步。只把候选结果和实际证据带回父会话，不把内部推理当成交付物。
- 最终用简短中文给出结果、实际依据和未解决的阻塞，不汇报隐藏推理或代理数量。

## 模式范围

本 Skill 由五个工作模式共用。遵守当前模式的常规权限、工作区和表达规则；本 Skill 不修改人格文件，也不改变无限制模式的既有权限边界。
