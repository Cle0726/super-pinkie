# Formats

One workflow, three shapes. Pick the format in the brief; it sets the length, the structure, and the pacing.

## Launch video (under 2:00, including the end card)

For a launch post, a community post, a homepage. It shows what the product does and how to start, then asks for
one action.

1. Hook (5-10 s): what this is, and what the viewer will see ("a quick tour, then how easy setup is").
2. Two to four product beats (15-35 s each): each one job, done on screen with real data. Lead with the least known
   capability; the example data should make the value obvious in one number (10 searches a month against 2,400).
3. How to start (15-25 s): the one step that gets someone going (a setup prompt, a sign-up), then what they get.
4. Call to action over the end card (5-10 s): the offer, spoken over the product's card.

Budget the length on the storyboard (each card has seconds) before recording; a take usually runs 15-25% longer than
the plan. The worked example: [examples/openseo-launch](../examples/openseo-launch/) (dashboard tour, competitor research, keyword ideas, "and much
more", agent setup and skills, end card; 1:54).

## Feature demo (30-90 s)

One feature, end to end: the problem in a sentence, the feature doing it on real data, the result, where to find it.
Two or three scenes. Good for a changelog, a docs page, or a reply to "how do I...".

## Tutorial (2-8 min)

A task the viewer will repeat, step by step: every click shown, every field filled on screen, labels that name the
step ("1. Connect Search Console"). Slower: hold each result a beat longer, drift less. Long waits (a crawl, an agent
run) become a cut to the finished state or a short screen recording in a recording pane, never real time. Chapters:
note each scene's start time for the video description.

## For all of them

- One idea per scene; a scene runs 5-40 s. Split a longer one.
- The first frame is the poster: the whole app at rest, no fade.
- Labels: one per beat, a few words ("Research competitors"), never a sentence.
- The example data is part of the script: choose it for how it reads at a glance, for this audience, in their language.
