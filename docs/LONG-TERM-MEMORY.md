# CLE Kk 独立长期记忆

长期记忆不是把整段聊天永久塞进上下文，而是把未来仍有用的少量事实保存下来，在相关任务中重新召回。

## 隔离边界

四个主模式使用四个物理文件，任何查询都只打开当前工作区里的 `memory/.clekk/records.json`：

- 唠嗑：`~/.openclaw/workspace/memory/.clekk/records.json`
- 项目：`~/.openclaw/workspace-project/memory/.clekk/records.json`
- 想法：`~/.openclaw/workspace-thinking/memory/.clekk/records.json`
- 无限制：`~/.openclaw/workspace-unrestricted/memory/.clekk/records.json`

项目模式还会按绑定项目目录的摘要值建立二级命名空间。两个项目即使使用同一个 project agent，也不能互相检索记忆。未绑定项目的会话按会话隔离。

子代理可以读取父会话当前模式的记忆快照，但不能直接修改长期记忆库。这里的只读只针对记忆库，不限制文件读写、终端、浏览器、全盘访问或任何既有工具。

## 写入与召回

- 用户明确说“请记住”“以后不要”“永远”等稳定要求时，宿主先做一次确定性保存；重复内容按 key 更新，不重复堆积。
- 模型通过 `clekk_memory` 工具保存偏好、纠正、稳定事实、项目决策和参考位置。工具成功前不能声称已记住。
- 密码、令牌和密钥不会写入。临时待办、隐藏推理、子代理争论和工具流水也不属于长期记忆。
- 每轮只召回当前模式中最多 8 条、最多约 6000 字符的相关或置顶记忆。历史内容以 JSON 字符串引用，明确作为数据而不是系统指令。
- 本轮用户新说法和真实项目现场永远优先于旧记忆。

## 用户管理

侧边栏底部的“记忆匣”只显示当前模式、当前项目的内容，支持搜索、新增、编辑、置顶、单条删除和二次确认清空。所有操作都走本机网关，不产生聊天气泡，也不会复制到其他模式。

## 与上下文压缩的关系

上下文压缩负责让一条长会话继续运行；长期记忆负责跨会话保留稳定信息。压缩前的 memory flush 仍然保留，压缩后会重新加载当前模式的基础记忆文件，并在下一轮重新检索长期记忆。两者互补，不互相替代。
