# 会话与项目目录

旧版左侧项目只有浏览器分组和 `projectFolders` 路径；创建会话只传 category，没有把目录交给模型工具。这是模型继续在模式默认 workspace 找文件的原因。

## 使用

四模式都一样：左侧项目选择具体文件夹，然后点该项目旁的「＋」创建会话。项目内的「新会话」也会留在这个项目里。输入框顶部显示完整的当前目录。

已有分组会在打开其中会话或发消息前绑定。只有名字、没有文件夹的分组必须先选择目录。绑定失败会阻止消息发送，并显示错误；不是仅往聊天消息里塞一句路径提示。

会话第一次绑定后目录固定。换项目要另建会话，不能把旧聊天历史移动到另一个工作目录。移除侧栏分组不会删除文件，也不会解除旧会话的执行约束。没有加入文件夹项目的普通聊天保留原先行为，不能当成已经开启项目隔离。

## 执行约束

- `pinkie.project.bind` 是经过网关身份验证的 operator.admin 方法，按完整会话键（包括模式 agent）保存目录。
- `before_prompt_build` 给当前轮附加项目范围说明，原人格文件保持不变。
- `before_tool_call` 把文件工具相对路径解析到项目目录，验证 `..`、绝对路径和符号链接；外部项目读写会被阻止。
- macOS shell 命令实际在该目录启动，并由 `sandbox-exec` 限制文件访问。系统运行库、已知共享 Skill 目录只读，项目与每会话临时目录可写。不能退回非隔离终端或切到另一台主机。
- 进程工具仅接受本会话启动的进程。跨会话派工、全局记忆搜索、远程主机与未经适配的工具不能在项目会话里绕过目录；普通网页搜索仍可使用。
- OpenClaw 自身更严格的工具限制仍然生效。例如某版本的 `apply_patch` 只允许原 agent workspace，遇到拒绝要改用受约束的 `edit/write/exec`，不能放宽全局配置。

这是一套针对本机四模式的项目工作范围约束，不是针对同一系统账号中恶意管理员的安全边界，也不会清除旧消息已经包含的其他项目信息。需要彻底干净的上下文，应在目标项目新建会话。派对群聊继续使用它已有的独立项目目录、独立历史和 Codex 权限确认流程；这里的钩子仅针对四个模式 agent。

记录位于 `~/Library/Application Support/SuperPinkie/project-scope/bindings.json`。安装备份原配置，不修改四模式人格、密钥或聊天数据库。App 更新包包含插件和安装脚本。新版本的首次安装需要网关重新加载插件；界面不能确认连接时不会声称保护已生效。

机制依据：[OpenClaw 官方插件钩子](https://docs.openclaw.ai/plugins/hooks)。
