# 会话与项目目录

旧版左侧项目只有浏览器分组和 `projectFolders` 路径；创建会话只传 category，没有把目录交给模型工具。这是模型继续在模式默认 workspace 找文件的原因。

## 使用

四模式都一样：左侧项目选择具体文件夹，然后点该项目旁的「＋」创建会话。项目内的「新会话」也会留在这个项目里。输入框顶部显示完整的当前目录。

已有分组会在打开其中会话或发消息前绑定。只有名字、没有文件夹的分组必须先选择目录。绑定失败会阻止消息发送，并显示错误；不是仅往聊天消息里塞一句路径提示。

会话第一次绑定后主项目固定。换主项目要另建会话，不能把旧聊天历史移动到另一个默认工作目录。移除侧栏分组不会删除文件，也不会解除旧会话的项目锚点。没有加入文件夹项目的普通聊天保留原先行为。

## 项目锚点与全机访问

- `pinkie.project.bind` 是经过网关身份验证的 operator.admin 方法，按完整会话键（包括模式 agent）保存目录。
- `before_prompt_build` 明确告诉模型：所选目录是默认工作重心，不是权限边界；原人格文件保持不变。
- `before_tool_call` 只把文件工具的相对路径解析到主项目。绝对路径、`~` 路径和通向其他目录的符号链接都可以正常使用。
- shell 命令默认从主项目启动；明确提供其他绝对工作目录时按原样使用。插件不再套 `sandbox-exec`，也不改写命令、主机、网络或提权参数。
- 浏览器、图片、网络、进程、记忆和未来新增工具全部放行给 OpenClaw 自身处理，不再因为绑定项目而被插件拦截。
- 子代理仍走当前会话的标准派生并继承项目锚点，不硬编码切换 agent 或 workspace；相对路径继续落在同一主项目，绝对路径仍可访问全机。

这套机制适用于本机四个聊天模式。派对空间和灵感圆桌也使用同一语义：所选项目是默认目录，不是全机访问边界。派对空间仍保留每次派工的“只读 / 允许修改”确认；只读任务可读取全机但不能写，允许修改的任务可按任务访问本机文件与已配置工具。

最终可访问范围仍受用户本次授权、macOS/Windows 系统隐私权限以及具体工具能力影响；项目插件本身不再额外缩小范围。

记录位于 `~/Library/Application Support/SuperPinkie/project-scope/bindings.json`。安装备份原配置，不修改四模式人格、密钥或聊天数据库。App 更新包包含插件和安装脚本。新版本的首次安装需要网关重新加载插件；界面不能确认连接时不会声称保护已生效。

机制依据：[OpenClaw 官方插件钩子](https://docs.openclaw.ai/plugins/hooks)。
