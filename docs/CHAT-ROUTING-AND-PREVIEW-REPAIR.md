# 会话、Claude 来源和文件预览修复

本轮从当前安装的「超級碧琪.app」复制再修改。其他会话正在做的学习台、浏览器、压缩动画等内容，以安装包现有内容为底稿保留。App 由用户自行重启。

## 问题和改法

- **新建、切换会话误进学习台**：之前每个会话默认进入「今日」。现在选择任意学习会话都进入聊天，包括重新选择同一个会话。学习台只通过入口打开。题目、作答结果和上次学习台位置仍按会话保留；主动回到舞台时继续原题。模式与会话所属智能体不一致的过渡阶段，不挂载学习台。
- **发送报 `editor.setModel` 空对象错误**：切换项目目录时，尚未加载的标签没有 model，编辑器也没有创建；两个 undefined 被误判成「当前编辑器的 model」。现在只有编辑器和文本 model 都存在且对应时才解绑。文件现场同步、项目绑定和发送顺序继续保留。
- **Claude 两个来源混在一起**：保留 Claude 账号池；Antigravity 池单独显示「·At」。仅将 At 池内部的 Low / Medium / High 合并到同一个滑杆入口，不把无后缀的账号模型合进 At。
- **预览出现两个窗口**：以前浏览器 1.5 秒没有回执，就另开 iframe 预览层。现在原生浏览器接管后，慢回执、失败和超时均不再创建第二个预览层；同一文件连续点击共用一次请求。
- **MD 文件显示源码**：原生浏览器预览 `.md` / `.markdown` 时，使用本地已有的 Markdown 解析器与清理器，排版标题、加粗、引用、列表、表格和代码块。按日夜模式显示，窄窗口正常换行。只在打开 MD 时加载，不给聊天页增加解析器开销。保存到下载保留原文件。

## Claude 两个池的边界

| 账号池，单独保留 | Antigravity 池，单独保留 |
| --- | --- |
| `mm/claude-sonnet-5-5` | `mm/claude-sonnet-5-5-{low,medium,high}` → `Claude Sonnet … ·At` |
| `mm/claude-opus-5-5` | `mm/claude-opus-5-5-{low,medium,high}` → `Claude Opus … ·At` |

六个 At 端点来自用户提供的上游来源截图，并与当前配置的真实模型 ID 核对。上游 `/models` 的 `owned_by` 全部写作 `openai`，不足以区分这两个池，不能据此合并。模型 ID、账号配置和密钥不做删除或改写。

At 的思考等级编码在端点 ID 中；适配器参数使用 `off`，与端点本身的 Low / Medium / High 是两回事。前端和后端都核对实际端点，避免缓存中的旧选择造成错误路由。

| 滑杆档位 | At 实际端点及原设计逻辑 |
| --- | --- |
| 关闭 / Minimal | 最低可用端点，保留原有简短回答逻辑 |
| Low / Medium / High | 同一 At 池内对应端点 |
| XHigh | 最高可用端点 + 1 份独立解答 + 批评 |
| Adaptive | 按本条难度选择 Low 或 High；难题继续 XHigh 流程 |
| Max | 最高可用端点 + 2 份独立解答 + 批评、交付验收 |
| Ultra | 最高可用端点 + 3 份独立解答 + 批评兼仲裁、交付验收 |

如果某个端点不可用，就在同一池内选择实际可用的最近等级，再走原有补充流程。不会跳进另一个池。其他模型的九档规则不改。

## 验收标准和证据

- 新会话、切换旧会话、重复选中、模式切换都进入聊天；主动打开学习台仍可使用。切走后回到舞台，题干和已作答状态一致；旧会话的延迟事件不能关闭当前舞台。
- 没有 Monaco 编辑器时，未加载标签、图片和页面标签可正常关闭；切换根目录后可以完成发送前的工作台现场同步。已有文本 model 仍先解绑再释放。
- Sonnet、Opus 的两个池各自可选；At 两个系列共 18 次九档操作不越池；选择账号池后，Ultra 也不把它换成 At。常用模型仍保留最近六个。
- 服务端从旧的 At Medium 选择也能纠正九档路由；独立解答和批评使用相同 At High 端点，适配器参数不冒充可调原生档位。端点确认失败时保留未发送消息。
- 浏览器回执超过原来的 1.5 秒、明确失败、8 秒超时及连续双击，都不会再打开第二个预览层。
- 使用真实 Swift 文档生成器生成 HTML，在 Chromium 和 WebKit 验证标题、表格、代码、日夜模式、360px 宽度及正文转义；不加载外部依赖。
- 原生文件访问测试通过；编译使用当前 App 的 Launcher.swift、BrowserControl.swift，二者源码逐字节保留。只在 MaterialPreview.swift 加 Markdown 文档生成与对应页面脚本策略。

自动测试使用独立端口、临时会话和可控模型执行器，不发送到用户真实聊天，不将其称作 Claude 付费实测。测试入口：`tests/study-desk-chat-entry.test.cjs`、`tests/workbench-editor-lifecycle.test.cjs`、`tests/antigravity-routing.test.mjs`、`tests/material-browser-preview.test.cjs`，以及 `tools/work-panel/` 的模型来源、原生 Markdown 浏览器验收工具。
