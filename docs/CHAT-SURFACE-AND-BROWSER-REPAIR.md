# 聊天界面与内置浏览器修复

## 修复范围

- 启动默认聊天首页，编辑器改为手动打开。保留文件和标签页记录。
- 恢复原有九个强度档位和字体特效，保留 Max、Ultra 自定义复核流程。模型原生能力较少时兼容映射，固定档位模型使用已有真实路由；提示中说明映射，不伪造新的模型能力。
- 修复发送时的布局收缩被误判为主动上翻，以及 Lit 复用消息节点时锚点跟错消息的问题。
- 副阅读页隐藏输入框、模型选择和右侧工具栏。只匹配原生副页标记，主页面保持原样；会话切换、关闭副页仍可用。
- 草稿文字按网关和会话保存到持久存储，输入法组合期间也即时备份。原来的临时发送队列不因为备份而变成重启后自动发送的任务。发送或主动清空后删除对应草稿；副阅读页不能清掉主页面草稿。
- 当前运行过程和最近一轮过程显示分段文字、思考和工具摘要；旧轮次仍按需展开，长工具历史继续分批挂载。保留用户手动折叠的选择。

## 浏览器逻辑

所有模式共用现有 `app_browser`，没有另开外部浏览器或安装第三方浏览器运行时。参考 [agent-browser](https://github.com/vercel-labs/agent-browser) 的精简快照和稳定引用设计，以及 [Playwright MCP](https://github.com/microsoft/playwright-mcp) 的结构化观察方式，控制代码独立实现，继续使用原有 WKWebView。

- 默认返回当前屏幕的精简正文与控件引用；支持只观察某个区域、按名称定位、读取正文、增量快照和同源 iframe、开放 Shadow DOM。
- 默认等 DOM 可操作，不等所有图片和广告。点击前检查位置稳定、遮挡和可用状态；动态表单按条件等待，支持内部表格滚动。
- 连续表单步骤可批量执行，批量结束观察一次。跨模式写操作不能插进同一批次。
- 失败返回已完成步骤及不确定状态，先观察再重试；不会重放已完成前缀。取消同步停止原生等待和后续重试。
- 保留原有连接验证、用户接管和网页协作保护。

## 验收标准与证据

| 项目 | 标准 | 验证 |
| --- | --- | --- |
| 草稿 | 关闭临时会话仍恢复；发送后不复活；会话独立 | 原生存储单测、完整渲染器新浏览器上下文 |
| 分段过程 | 运行中可见说明、渐进思考和读写改状态 | 真实编译渲染器与隔离网关逐事件记录 |
| 阅读副页 | 无底部输入区和侧工具栏；主页面可用 | 完整页面布局与截图检查 |
| 长聊天 | 发送到最近；主动上翻不被拉走；旧分页仍能返回 | 180 条历史与流式生成回归，阅读锚点误差小于 1px |
| 高强度浏览器 | 重复动态表单不误点、不重复提交、不丢失结果 | Chromium/WebKit 各 500 轮、各 3000 次工具请求；原生 WebView 200 次连续操作 |
| 浏览器响应大小 | 大页面观察内容有界 | 6000 个后台控件测试页约 70KB 缩至 7KB |
| 安装 | 保留现有原生外观和学习交互，签名有效 | 定向文件清单、保护文件校验、deep strict 签名验证 |

测试数据位于任务工作目录 `work/`。浏览器压测使用受控动态页面，实际网站的网络、服务端速度与交互实现仍影响耗时；未证明每个网站或长达数小时的运行都同样快。跨域框架、封闭 Shadow DOM、Canvas、文件弹窗和要求原生手势的控件转用可视化操作，避免循环无效点击。

本次不接管 Claude 正在修改的学习交互模块。发布时保留当前 App 的窗口和素材预览源码，仅合并浏览器控制层，并对现有渲染器做局部修改。
