# 全局实时回复与工作进度

覆盖唠嗑、项目、想法、无限制四模式，以及派对空间。不是把已完成的答案伪装成打字动画。

## 四模式

- 复用 OpenClaw 原生文字增量、工具 start/update/result 和公开 commentary，保留原生会话路由与滚动管理。
- `laolao-progress.js` 按版本做一次原生设置升级，开启工具显示、保留公开阶段说明；以后用户手动关闭会被尊重。不改变推理等级、模型、容量或人格，也不打开隐藏思维。
- 流式正文显示「实时输出中」；真实工具事件使用可折叠进度卡，错误状态单独标色。工具返回的图片和消息图片可点击放大，不另造一份消息。
- 皮肤不再覆盖真实工具路径、命令和输出。工具标题显示中文用途和真实工具名。
- 两个 HTTP 代理使用 `HTTPResponse.read1()` 转发，首个小块无需等待 64KB 或响应结束。一旦响应开始，传输异常只结束当前流，不偷偷重发可能有副作用的请求。首包前原有重试策略保留。

## 派对空间

- 紫悦使用本机 `codex app-server` 的 stdio JSON-RPC：独立 ephemeral 任务、既有模型/上下文配置、只读或已批准的项目写入权限。MCP 桥仍禁用，服务端审批请求不会自动放行。
- 碧琪与云宝仍使用独立 `openclaw agent --local --json` 和每次隔离配置，工具 `deny: ["*"]` 不变。显式 Node preload 只订阅本进程的公开 assistant/tool 事件。不会访问其他窗口、历史或事件。
- OpenClaw 版本没有公开事件导出时明确显示降级说明，仍可接收完整结果，不伪造实时工具状态。
- 碧琪的结构化调度只流式展示顶层 `message`；`tasks` 必须完整解析后才生成待确认派工。半截 JSON 绝不执行。
- SQLite 保存稳定的 `(task, stream_key)` 消息，约 70ms 合并写入。最终内容原位确认，不追加重复回复。隐藏 reasoning 事件不保存、不展示。
- `/api/rooms/:id/events` 使用本机同源 SSE 推送变更。初次连接/重连发送一致快照，后续根据持久事件游标发送变更。浏览器按消息 ID 合并，不重复插入；切群关闭旧连接并校验 room/epoch。
- 保留当前正在阅读的位置和展开的工具卡。取消后拒绝迟到内容；重启把未完成气泡标为中断，已输出文字保留。

未连接的其他成员不会因此自动获得工具或流式能力。实际速度仍取决于上游是否发送增量，不能让一个仅返回完整结果的服务凭空产生真实流式输出。

## 项目与会话侧栏

- 侧栏独立管理自己的 DOM，不再搬动原生列表节点；按当前模式显示置顶、文件夹项目、最近会话，并提供名称搜索。
- 项目旁的 `＋` 会先校验目录，再创建独立会话并绑定目录，绑定成功才切过去。重复名称自动编号，连点合并，名称竞争只重试同一会话键。
- 普通新会话按钮在当前项目中继续创建；没有项目时创建当前模式的普通会话。原来的置顶和项目分组保留。
- 会话菜单支持重命名、置顶、归档；归档入口支持恢复。归档不删除记录、不解除项目绑定。已绑定目录的会话不能直接搬去其他目录，以免历史和文件混用。
- App 使用系统文件夹选择器；浏览器可以输入完整路径，由后端校验。移除侧栏项目只移除分组，不删除文件或聊天。
- 这些是常用会话管理能力，不代表已实现 Codex 的所有高级功能（例如完整的 Git 工作树管理）。

## 验证

```sh
python3 -m unittest discover -s tests -p '*stream_test.py'
node --test tests/progress-ui.test.cjs tests/sidebar-sessions.test.cjs
# 独立离线页面，不调用模型、不改项目：
python3 tests/stream_preview.py
# 可选真实接口检查，会产生少量模型用量；只创建临时测试会话：
python3 tests/stream_live_smoke.py --backend codex
python3 tests/stream_live_smoke.py --backend openclaw
python3 tests/stream_live_smoke.py --backend pinkie
```

部署需要同步 UI、派对服务与代理，并重新加载网关使进度约定生效。不得覆盖用户自己改过的模型容量与压缩策略。
