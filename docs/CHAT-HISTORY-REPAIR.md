# 聊天记录、渲染与滚动修复

日期：2026-10-23。初始范围为仓库代码与离线验收；其后用户授权更新已安装 App，安装结果见文末追加记录。

## 修复计划

1. **历史同步与完整回看**：采用服务端 `nextOffset`；检测游标停滞和跨页会话实例变化；有界重试。初次恢复只按页读取近期记录，约 512 条是初次加载目标，不能作为整个会话的可回看上限。保留完整已取得页面及真实游标，向上翻页能持续加载到最早一条；后续回复和重连不能裁掉已加载的旧记录。相同 ID 的正文、状态变化也必须同步。
2. **滚动意图**：为自动跟随分配可取消的令牌；用户滚轮、触摸、拖动滚动条或键盘翻页后，取消尚未执行的自动滚动。发送、回复结束、历史同步共用此规则。旧回调不能移动新会话或新一轮的视口。
3. **阅读位置**：旧聊天链用可见消息 ID 和视口偏移保存位置，覆盖历史裁剪、补载、卡片展开和状态移除；明确贴底时才跟随底部。容器宽度变化后重新测量离屏占位。各分栏独立管理，清理销毁的观察器和缓存。
4. **渲染减负**：2026.10 直接使用内核已有的虚拟列表，删除旧补丁搬移 Lit DOM 和全页面扫描的干扰。2026.7 旧链先从已加载数据中选取 100 条一页，再构建 Lit 时间线，提供上一页、下一页、回到最近和继续加载更早消息；长过程额外保留最多两条用户/工具上下文。旧过程卡、较早步骤在展开时由 Lit 创建，关闭时由 Lit 卸载，较早步骤每批最多 80 条。保留用户手动展开状态。流式处理限定在当前卡片和变化节点。
5. **当前 C.le. 插件**：让会话渲染装饰只处理新增/变化节点，避免每次流式更新重扫整页；保持内核对虚拟列表和滚动位置的所有权。复用安全的视口能力，避免两套虚拟化或滚动策略竞争。
6. **集成与回归**：更新资源版本和安装路径；修复过期的补丁测试 fixture，补行为测试。构建插件，在隔离页面使用合成历史做长会话和滚动验证，不读取真实聊天或调用模型。
7. **追加消息**：追加确认与待发送分开；任务运行中也清理已有持久化送达证明的卡片。每条证明只消费一次，保留用户故意重复的消息。送达不确定时保留单一消息卡，不自动重发、不另复制到输入框；已接受的追加不再提供会造成重发的“改为结束后发”。

## 验收标准

| 项目 | 场景 | 通过标准 |
| --- | --- | --- |
| 分页 | 返回数量与 `nextOffset` 不同；有内部消息和投影记录 | 严格按服务端游标推进，无重复、乱序和遗漏；游标停滞不会循环 |
| 会话隔离 | 分页期间切会话、同 key 重置、连接换代 | 旧结果不写入新会话；实例变化丢弃整批结果并有界重试 |
| 长任务 | 1 条用户输入 + 519 条工具记录；更多内部控制消息 | 初次加载有预算，页面边界不能截出缺口；尚有更早记录时保留真实分页状态，继续翻页能回到用户开头与最早记录 |
| 完整历史回看 | 至少 1,200 / 10,000 条服务端记录，逐页回看后返回最新 | 能看到第一条和最后一条，无重复/遗漏；初次不预加载全量，屏幕外渲染与历史数据可达性分别管理 |
| 回看期间更新 | 已加载更早页面时收到新回复、断线重连或最新尾页刷新 | 保留已加载历史与当前阅读锚点，不把分页改成结束，不强制滚到底部 |
| 正文更新 | 消息 ID 相同但正文或结束状态改变 | 可见内容更新，不能只比较 ID |
| 用户滚动 | 发送后、回复到达后 120ms 内向上滚；触摸、键盘、拖滚动条 | 待执行跟随取消，后续旧回调不会滚底；新发送才重新建立跟随意图 |
| 阅读保位 | 裁剪旧消息、补载历史、展开/收起卡片、移除状态 | 旧链当前可见消息的纵向偏移误差不超过 2 CSS px；用户已改变意图时不做旧位置恢复 |
| 布局变化 | 收展侧栏、单/双栏切换、改变窗口宽度 | 不依赖 `window.resize` 才重测；两栏互不抢滚动 |
| 懒渲染 | 长过程卡未展开、展开、关闭、继续加载 | 收起时无步骤正文 DOM；展开按批生成，关闭卸载；用户展开状态不被完工改写 |
| 原生虚拟列表 | 合成 1,000 与 10,000 条历史，固定视口和位置 | 渲染行数量由视口和内核 overscan 决定，不随历史总量线性增长；无直接搬移/删除 Lit 所有的消息 DOM |
| 旧版本地分页 | 已加载 1,000 / 10,000 条普通消息，逐页浏览并追加 20 条 | 普通消息每页最多 100 条；逐页可访问全部消息；新追加不改变旧页首尾；到已加载数据边界才请求服务端 |
| 连续回看性能 | 10,000 条已载历史，真实滚轮连续 20 次 | 消息行 DOM 不随累计页数线性增长；检查 Long Tasks API，不由补丁在滚动事件中重建全部历史；单独记录补页峰值，不把分页耗时当作持续滚动帧率 |
| 增量处理 | 连续更新当前回复，历史卡数量增加 | 不反复遍历全部历史节点；装饰仅处理新增/变化区域；无观察器自触发循环 |
| 生命周期 | 连续切会话与分栏，激活/销毁插件 | 不残留定时器、观察器或已销毁消息引用；无 Lit 标记损坏或未捕获异常 |
| 追加消息 | 运行中已收到追加；终止事件丢失；同文字多次追加；送达不确定 | 持久化确认后移出队列，不等整轮结束；不出现“等会儿发＋已追加”冲突；一条证明只消除一张卡；同一提交只调用一次发送；未知结果不自动重发 |
| 功能回归 | 发送、工具、最终回复、续跑、队列、复制与代码块 | 相关回归测试全部通过；原生历史和消息正文保持完整 |
