# 消息内交互学习：实施与验收

范围：在碧琪聊天消息里直接操作英语题卡、参数函数图和流程演示；沿用现有模型、判题、学习记录及主题。

实施顺序：

1. 学习服务保存交互定义、参数、步骤和作答草稿；所有记录绑定学习会话，题目答案继续仅留在服务端。
2. 原生消息渲染器提供空的交互挂载槽，前端只管理自有节点，不挪动原生消息节点。
3. 题卡接现有提交/讲解路径；函数参数和流程选择即时本地响应，保存状态不触发模型请求。
4. 可见卡片按需加载；切换会话、分页、关闭和后台状态正确释放观察器与事件，保留完整历史数据。
5. 隔离服务与真实原生渲染器做浏览器验收，确认后更新已安装App。

验收标准：

- 选择题、填空和简答在消息内作答并逐题结算；答案和私有评分点不出现在未作答的公开数据中。
- 草稿、参数和步骤保存完成后，重开App/会话或翻回历史可恢复；超过24条仍可按ID读取。
- 跨会话ID访问、过期版本写入、无效参数、HTML/脚本内容均不能改变其它内容或执行代码。
- 调滑块、点击流程步骤不发送聊天消息；下一轮对话能读取当前参数和步骤，但操作不被算成掌握。
- 320px窄屏无横向溢出；卡片不改变聊天区宽度；加载与错误状态有可用恢复入口。
- 历史页保留摘要，交互按可见范围加载；空闲没有持续DOM写入，翻阅长历史不批量启动动画或网络轮询。
- 原有聊天分页、滚动、学习记录、模型选择器、安装脚本和相关回归继续通过。

使用入口：学习会话里开启“互动学习”后可以直接作答题卡；也可以要求碧琪“画一个可调参数的二次函数图”或“演示Hadoop的Map、Shuffle、Reduce流程”。新生成的交互组件显示在对应消息中，旧的普通文字不会自动变成卡片。首版函数支持一次、二次和正弦函数；流程支持2–12步。

浏览器验收中的讲解由隔离模拟模型返回，使用真实后端判题与记录；未向用户真实聊天发送验收消息。
