## Windows 端 11-12 晚：自查——界面状态以后端为准、交付门禁的误报（Mac 端先 `git pull`）

先合了 Mac 端的 `install/unify-1112-live`（和这条分支比只多了换模式头像 avatars7，无冲突）。然后把下午那一版和交接里还开着的项回头查了一遍，重点是「界面显示的和后端实际不一致、状态不实时、显示假数据」。还是没合 main、没发版、没装进 App。

**改了什么：**

1. **交付门禁：活交给子会话后误报**（`index.mjs` 的 `effectVerificationReason` 和执行证据检查，`session-lineage.mjs` 新增 `isChildDelegation`、`latestChildReport`、`SESSION_WAKE_MARK`）。上面「还留着的」第一条（开了跨模式子会话后多提醒一次）查清了，而且不只跨模式：只要是改文件的活交给子会话，**开子会话那一轮**和**汇报叫醒父会话那一轮**都会被判「执行型修改任务没有主机确认的文件变化」（叫醒轮沿用用户上一条原话，父会话这一轮只读文件核对，自然没有改动）。现在：这一轮真的开出了子会话（结果里有 `:pinkie-child:` 的 key，只提卡片不算），或者这一轮是被一份「做成了」的汇报叫醒的，就不要求父会话自己有文件变化——改动由子会话自己的门禁把关。汇报是「没做成」时照旧拦，父会话不能把没做成转述成做成；父会话在叫醒轮自己动了文件，照常要验证。`sessionReport` 也进了门禁的存档（snapshot / restore）。
2. **`pinkie_mode_ask` 的长答案被当成没问过**：门禁存的工具结果最多 12000 字，答案长时 JSON 被截断、整段解析失败。现在解析不了就在原文里找 `key` / `answer`。
3. **Windows：命令写出的文件门禁看不见**（`execTargetPaths`）。带反斜杠的路径原来一律丢掉（Mac 上反斜杠是转义），Windows 路径全是反斜杠，于是碧琪用命令生成的 PPT、视频、网页一个都认不出来，误报「没有主机确认的文件变化」。现在只在 Windows（`path.sep === '\\'`）上把反斜杠当分隔符；另外认引号里带空格的 `C:\…` 路径和 PowerShell 的 `Set-Content` / `Out-File` / `Copy-Item` 等写文件命令。Mac 上行为不变。
4. **Windows：勾检查点被当成改了代码**（`captureVerificationEvidence`）。判断记账文件用的是 JSON 文本里的路径，Windows 的 `\` 在那里是 `\\`，正则只认一个，于是长跑 / 加强档里「先跑测试、再勾检查点」会让测试证据作废，提醒「改完之后还没跑测试」。核心测试集里那两项「改动前就失败」的（`marathon keeps going…`、`ticking the on-screen plan…`）就是它，现在过了。
5. **会话偏好：界面只显示后端真的存下的**（`session-prefs.mjs`、`laolao-session-tools.js`、`laolao-composer-tray.js`）。
   - `pinkie.session.prefs.set` 回存下的那一份（原来只回 `{ok:true}`）；界面按它画。「这个会话按效率来」这类提示只在后端确实存下时才说，没存上就说没改成（老网关不认识 `pace` / `lens` 时原来会提示成功、按钮又弹回去）。
   - 读后端失败时，原来把默认值（联网开、风格默认）当成这个会话的设置缓存并显示，之后再也不读。现在：读到过就沿用上次的；从没读到就把按钮停用、写「还没读到这个会话的设置，会自动重试」，模式按钮不显示，工具菜单里这两行也灰掉、不显示开关和「默认」，6 秒后自己再读。
   - 换会话、切回窗口、网关重连时都重新读一次（快速提问小窗或别的窗口改过的要看得到）。每 1.5 秒的重画循环不会在一次读取没回来时叠请求。
   - 风格 / 工作程度 / 取向在下一轮组装提示时才生效：碧琪正在回答时改，提示会说「这一轮已经在回了，从下一条消息开始」。联网开关是调用工具时现读的，立即生效，不加这句。
6. **首页：等空白会话时被换掉会卡在「忙」**（`laolao-startup-home.js`）。发送时空白会话还在备，等待期间首页重进或换了会话，原来直接返回、`busy` 留着，之后首页的发送全被吞掉。

## Windows 端 11-12 下午：输入框和首页的 BUG、模式专属选项、关窗清理（Mac 端先 `git pull`）

**改了什么：**

1. **首页挂在一个空白新会话上**（`laolao-startup-home.js`）。原来首页借用这个模式上一次的会话：模型、思考强度、上下文显示的都是旧会话的，选模型也改在旧会话上；发送时才新建会话再跳过去，新会话回到默认。现在进首页就备好一个没发过消息的会话（列表里有空白的、且 `chat.history` 确认一条消息都没有才复用，否则 `createSession({quiet, stay})` 新建，不弹提示、不自己跳），输入框下面那一排就是新会话自己的状态，发送直接在这个会话里走，不再建、不再跳。它发出第一句话之前不进侧栏，也不出现在「继续之前的工作」里。备不出来（网关没连上、建会话失败）时退回老办法，并把首页上看到的模型和思考强度带到新会话（`carrySettings`）。模式转场进行中不备、不换。

**在真网关 + 真模型上验过的（隔离副本，`mm/gemini-3-flash`）：**

**实测露出来、已经改掉的（都有测试）：**

1. 跨模式子会话落在目标模式的默认模型上，默认模型不可用时全部起不来 → 用户在父会话里亲自选过模型（`modelOverrideSource: user`）就带过去；网关不收这个模型再退回默认。同模式子会话不动。
2. 子会话自己那一轮出错，父会话什么都收不到 → 等 20 秒（`failGraceMs`，自动续接可能救回来）仍是出错，就送一份「没做成」汇报（卡片 `failed: true`，标题「…没做成」）并照常叫醒父会话。提问（consult）不走这条，它本来就当场返回 `failed`。
3. 开完子会话后模型去轮询（`sessions_history` / `sessions_yield` / `subagents`），等不到就自己把活重做一遍 → `user_asked` 的工具结果里也写明「汇报会自动送回并叫醒你，不要轮询、不要重做」。
4. 「替我去问想法模式」被交付前提醒判成「没有真实执行」→ `pinkie_mode_ask` 算这类请求的执行证据。
5. 用户明说「另开一个子会话」，项目模式的模型却用网关自带的 `sessions_spawn`（侧栏里看不见、不走汇报卡片）→ 每轮拦一次，指回 `pinkie_session_start`；模型坚持就放行。档位流程里的 `sessions_spawn` 不受影响。
6. 唠嗑 / 想法模式下 `code_check` 等代码工具跑到模式自己的工作区，而不是会话绑定的项目文件夹 → 跟着绑定走。

## 改了什么

### 1. 子会话：碧琪自己分工（`services/mode-architecture/session-lineage.mjs`）

原来的三种发起方式里，只有用户明说「另开会话」才会立刻开始，其余都是一张等用户点的卡片。用户大多不点，所以并行实际上很少发生。

新增第四种发起方式 **`in_scope`**：用户这条消息本身要的活里，互不依赖的一块直接开子会话并行做，不出卡片、不用点。

- 只在用户亲自发来的那一轮可用。内部续跑、汇报唤醒、心跳、记忆整理的轮次一律拒绝（报错文字会告诉模型改用 `own_initiative` 卡片）。
- 每轮最多 3 个，同时在跑的上限还是 4 个。
- 汇报回来会自动唤醒父会话去核对、合并（和 `user_asked` 一样，两次用户发言之间最多 3 次）。
- 范围外的后续（顺手发现的 bug、该补的说明）仍然只能是 `own_initiative` 卡片。**用户要了的活怎么分是做法，用户没要的活做不做由用户定**，这条线没有动。
- 构造参数 `autoSplit: key => boolean` 可以整体关掉（默认开）。目前没有接设置界面的开关。

### 2. 汇报不再只给父会话 400 字

原来父会话拿到的是子会话最后一条回复的前 400 个字形，结论经常被截在开场白里。现在：

- 卡片上还是显示 400 字。
- 父会话下一轮读到的是完整的那份，最多 6000 字（`card.full`）。读过之后 `full` 从 `session-cards.json` 里删掉，文件不会越积越大。
- 代理写的简报末尾自动加一句「你最后一条回复就是交回去的汇报：先写结论和成品在哪，再写验证过什么、还差什么」。用户亲自开的子会话原来就有类似的话，措辞改成和新行为一致。
- 卡片上「看完整简报」和实际发出去的简报现在是同一个函数生成的（`briefFor`）。

### 3. 跨模式：子会话可以开到别的模式里，也可以当场去问

- `pinkie_session_start` 多了可选参数 `mode`（`chat` / `project` / `ideas` / `learning`）。子会话建在那个模式的 agent 下，带着父会话的项目文件夹绑定，简报开头会说明是从哪个模式转来的。只能 `fresh`。
- 新工具 **`pinkie_mode_ask`**（`mode`、`question`、可选 `background`）：在那个模式里开一个只回答问题的会话，默认等 120 秒，把答案作为工具结果当场带回；父会话留一张已读的汇报卡片；那个会话答完就归档，不留在另一个模式的侧栏里。等不到就返回 `pending`，答案之后走普通汇报并唤醒父会话。每轮最多 3 次。
- 无限模式两头都不参与：不能从它发起，也不能转到它。
- 网关的父子关系只在同一个 agent 内成立，所以跨模式创建时**不传 `parentSessionKey`**，血缘只记在 `session-lineage.json`（多了 `mode`、`fromMode` 两个字段）。运行数上限、归档父会话时停止子会话、发消息、列表都改成把别的 agent 里的子会话一起算（`familyRows`）。
- `openclaw.plugin.json` 的工具清单、只聊天权限预设（`laolao-settings-user.js` 的 `CHILD_SESSION_TOOLS`）、老配置的启动迁移（`MINIMAL_CHILD_TOOLS`）都加上了 `pinkie_mode_ask`。

### 4. 模式推荐和时机提醒（`services/mode-architecture/session-hints.mjs`）

- 一条消息里列了几件互不依赖的大活、或者用户说了「同时」：提醒改成用 `in_scope` 直接并行，不再是提卡片。
- 新增【别的模式更拿手】：这条消息明显是另一个模式的专长、而当前模式自己的专长对不上时（项目模式里问配色审美、唠嗑模式里要写程序、任何模式里要系统地学），提醒碧琪用 `pinkie_mode_ask` 去问或把大活开到那个模式。同一个去处隔 6 轮才再提，「以后这类事可以直接去某某模式」只让它说一次。要系统地学、练、备考时会建议用户直接切到学习模式，因为学习台只在那边有。
- 判断用的是关键词，只在单方面命中时才提（「帮我做个好看的网页」在项目模式里不会被指到想法模式）。宁可漏，不乱指。

### 5. 四个模式的手册（`personas/{chat,learning,project,thinking}/AGENTS.md`）

「子会话」一节改成四种发起方式；后面新加一节「别的模式更拿手的事：替用户去问，不让用户跑」。四份手册这两节的文字相同。

### 6. 性能：打盹和自动减负（`ui/injections/laolao-rest.js`，新文件）

两件事，都不读硬件信息。

**打盹**（看不出差别）：

- 窗口在后台 20 秒，或 5 分钟没人碰鼠标键盘 → `away`：聊天背景氛围画布停在当前这一帧，不消失。
- `away` 而且碧琪上一轮结束超过 30 秒 → `rest`：小碧琪（`laolao-buddy-rig.js`）停在当前姿势，无限循环的装饰动画和循环视频暂停。有头有尾的出现 / 消失动画不碰。
- 鼠标、键盘、滚轮、窗口回前台、碧琪开始干活，任何一样立刻恢复。碧琪在后台干活时小碧琪照常动，只有氛围画布还停着。
- 开了「减少动效」、页面隐藏、启动动画或模式转场期间不打盹。

**自动减负**（只在真的掉帧时）：

- 页面在前台、有人在用时量帧间隔。连续三个 5 秒窗口里过半时间花在慢帧上（比屏幕正常帧间隔慢三倍以上且超过 50 毫秒）才降一级；连续 60 秒不卡升回一级。
- 两级：氛围帧率 20 + 画布清晰度「低」；再加粒子数量 0.5。都是进阶调节里本来就有的选项，画面上的东西一样不少。
- 通过 `PinkieTuning.setEase()` 盖一层临时值，不写进存储。只在「标准」档、用户没手动改过的那一项上生效。
- 进阶调节「特效」第一行是它的开关（默认开）。关掉后存储里多一个 `auto: false`；开着时存储内容和以前逐字节相同。
- 第一次降级时小碧琪说一句话，告诉用户在哪里关。

**这改了一条原来的说法：** `laolao-tuning.js` 和进阶调节页脚原来写的是「每台电脑看到的效果都一样，只听你的选择」。现在是「默认都一样，只有实测掉帧才临时省一点，可以关」。如果 Mac 端认为效果不该自动变，把 `clean()` 里 `auto` 的默认值改成 `false` 即可，其余不用动。

测试 `tests/rest.test.cjs`（13 项，假页面）。

### 7. 跨模式的会话接到界面上

原来点一个别的模式里的会话链接**什么都不会发生**：侧栏的 `navigateSession` 只认当前模式，直接返回。

- 卡片和侧栏遇到别的 agent 的会话，改发事件 `pinkie:open-session-in-mode`。模式切换器收到后把那个会话记成该模式的「上次会话」，再走正常的切换转场，于是落在那个会话上。会话已归档或不存在时，落到该模式平时的会话。
- 卡片标题带上模式名（「项目模式 · 搭脚手架 做完一轮」），链接写成「去项目模式打开 ›」。
- `pinkie_mode_ask` 的汇报卡片标题是「…的回答」，不给打开链接（那个会话答完就归档了）。后端汇报卡片多了 `consult: true`。
- 从别的模式转来的子会话，侧栏行前面有一个小标签（「项目」），顶上的「来自」写成「来自项目模式：…」。
- 父会话那一行多一个 `↗想法`（多个时是 `↗2`）入口，点了去那边。

## 没有验证的

- **没有跑任何真实模型。** 上面全部是单元测试（假网关）验证的。`in_scope` 和 `pinkie_mode_ask` 在便宜的小模型上会不会被用对、会不会滥用，要 Mac 端用真实额度看。
- **跨 agent 的 `sessions.create` 不带 `parentSessionKey` 是否被网关接受，没有在真网关上试过。** 这是整个跨模式功能最需要先确认的一点。
- `pinkie_mode_ask` 会让一次工具调用最多等 120 秒。网关对单次工具调用有没有更短的超时，没有确认；如果有，把 `askTimeoutMs` 调小即可，超时后的兜底路径是测过的。

- **打盹和自动减负没有在真实 App 或浏览器里看过。** 测试用的是假的页面对象。掉帧的阈值（三个 5 秒窗口、50 毫秒）是按道理定的，没有在慢机器上校准过；`document.getAnimations()` 在 WebKit（Mac App）里暂停无限动画后恢复是否平滑，也要 Mac 端看一眼。

- **界面是在 Edge 加假网关里看的，不是在真实 App 里。** 布局、文字、分工条四种状态、进阶调节的新一行都截图看过，四个视图零报错。没有验证的：点跨模式链接后**真的切过去并落在那个会话上**（假网关不走完整的切换）、WebKit（Mac App）下的样子、深色模式下分工条和侧栏新标签的颜色。
