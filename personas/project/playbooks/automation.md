# 打法：让电脑自己干活——定时、盯文件夹、批量处理、抓网页、自动操作

用户说「自动」，要的是**不用他再管**：关掉网页、关掉这个 App、明天开机，它照样在干活；出了错有记录；不想要了能一键停掉、卸干净。做不到这几条的，还不算「自动」。

## 一、先分清是哪一种「自动」

| 用户说的 | 其实是 | 做法 |
|---|---|---|
| 「每天早上 8 点帮我……」 | 定时 | 脚本 + 系统定时（Mac 的 launchd，Windows 的任务计划程序） |
| 「下载完的文件自动分好类」「有新照片就……」 | 盯文件夹 | 常驻的小程序（Python 的 `watchdog` 库），或 Mac launchd 的 `WatchPaths` |
| 「把这 500 个文件都改一下」 | 一次性批量 | 一个脚本跑一次，不用常驻 |
| 「价格降了提醒我」「有新公告告诉我」 | 定时查网页 + 通知 | 定时脚本 + 比较上次的结果 + 通知 |
| 「帮我在某某网站上自动填/点」 | 自动操作网页或软件 | 浏览器自动化或桌面操作（见 `AGENTS.md` 里讲本机桌面操作的那一节） |

## 二、安全三件事（每个自动化都要有）

1. **先演习再动手：** 第一次运行先只列出「打算怎么处理哪些文件」，不真的改；在一个测试文件夹里真跑一遍，确认结果对了，再接到真实文件夹。
2. **不删原件、能撤销：** 整理用移动不用删除；重名不覆盖（自动加编号）；每次操作写一行记录（时间、原位置、新位置），配一个按记录撤销的脚本。
3. **有日志：** 运行结果和报错写进一个日志文件，用户和我以后都能查到它到底跑没跑、为什么失败。

## 三、示范做法：自动整理下载文件夹

用户说「弄个自动整理下载的东西」，可以先按文档、图片、音频、视频、压缩包、安装包分类，原文件名保留，重名不覆盖，正在下载的 `.part` / `.crdownload` / `.download` 先跳过，等它下载完再整理。操作留记录，能撤销。

先在项目里的模拟下载目录做：整理程序和界面分开；程序作为独立进程运行，即使关掉网页、关闭这个 App，它也能继续盯目录。把网页关掉后，再放一个新文件进去，确认它真的被分好类，再说自动整理完成。仅仅给一个手动脚本、或网页每几秒扫一次，都还没做完「自动」。

要接真实下载目录或登录自启，先用按钮问用户；同意后，Mac 用用户级 LaunchAgent（不用 sudo），Windows 用用户级计划任务。命令里用绝对路径，带空格的路径要正确处理；同时交付停止、卸载、撤销入口。测试时只在隔离目录启动和停止自己的进程，不给用户的真实登录会话安装服务。没有权限或测试环境不允许安装时，说明「后台监控已实测；登录自启安装待确认」，不要谎称已安装。

## 四、装成后台常驻或定时（用户点头之后）

**Mac（用户级 LaunchAgent，不用管理员密码）：**
- 写 `~/Library/LaunchAgents/com.biqi.任务名.plist`：`ProgramArguments` 用 Python 的完整路径和脚本的完整路径；定时用 `StartCalendarInterval`（比如每天 8:00），常驻用 `KeepAlive`，盯文件夹也可以用 `WatchPaths`；`StandardOutPath` / `StandardErrorPath` 指向日志文件。
- 启用：`launchctl bootstrap gui/$(id -u) 那个plist的完整路径`；停用：`launchctl bootout gui/$(id -u)/com.biqi.任务名`。
- **Mac 的隐私保护会拦后台程序读「下载」「文稿」「桌面」：** 装好后一定要真的触发一次，看日志里有没有 `Operation not permitted`。有的话，要用户在「系统设置 → 隐私与安全性 → 完全磁盘访问权限」里给对应的程序打开权限——这是改系统设置，告诉用户点哪里，由用户自己点。
- 电脑睡着时错过的定时任务，醒来后会补跑一次。

**Windows（用户级计划任务，不用管理员）：**
```powershell
$action  = New-ScheduledTaskAction -Execute "完整路径\pythonw.exe" -Argument '"完整路径\整理.py"'
$trigger = New-ScheduledTaskTrigger -Daily -At 8am        # 开机登录就跑用 -AtLogOn
$set     = New-ScheduledTaskSettingsSet -StartWhenAvailable -DontStopIfGoingOnBatteries
Register-ScheduledTask -TaskName "碧琪-整理下载" -Action $action -Trigger $trigger -Settings $set
```
- 用 `pythonw.exe` 运行，不会每次弹出黑色窗口。
- 停用和卸载：`Unregister-ScheduledTask -TaskName "碧琪-整理下载" -Confirm:$false`。
- `-StartWhenAvailable`：电脑关机错过了时间，开机后补跑。

**交付四个双击就能用的入口：** 开始、停止、卸载（停掉并删除任务，保留用户的文件和日志）、看日志。再附三行说明：它在干什么、什么时候跑、出问题看哪里。

## 五、抓网页数据、监控价格和公告

- **先找正路：** 网站有官方接口、RSS、导出功能的，优先用它们。
- 静态页面用 `requests` + `BeautifulSoup`；要登录后才能看、或者内容是脚本加载出来的，用 Playwright。
- **守规矩：** 每次请求之间隔几秒，不并发轰炸；看网站的使用规则；不绕过登录、验证码和付费墙；涉及别人个人信息的数据不抓。
- 监控类：把上一次的结果存下来，只在**变化**时通知，不每次都发。
- 网页改版会让抓取失效：抓不到东西时写日志并通知用户，不悄悄地一直空跑。

## 六、怎么通知用户

- Mac 系统通知：`osascript -e 'display notification "降价了：89 元" with title "价格提醒"'`。
- Windows 系统通知：用 PowerShell 的 `System.Windows.Forms.NotifyIcon` 弹一个气泡提示。
- 手机上收到：企业微信、飞书、钉钉的群机器人 Webhook（用户自己建群机器人、把地址给我）；发邮件要邮箱的授权码，让用户自己填进配置文件，我不经手密码。
- 通知内容一句话说清发生了什么、要不要处理。

## 七、自动操作网页和软件

- 能用接口或文件解决的，不用模拟点击；模拟点击慢、容易坏。
- 必须操作界面时，按 `AGENTS.md` 里讲本机桌面操作的那一节：先截图看清、用真实的点击和输入、再截图确认真的变了。
- 发布、提交、付款、发送消息这类对外的最后一步，每次都等用户确认；密码和验证码让用户自己输。

## 八、验收

- 关掉界面后，真的触发一次（放一个新文件、或者把定时改成两分钟后），确认结果出现、日志有记录。
- 故意制造一个错误（文件被占用、网断了），确认它不会崩溃、日志里写清了原因。
- 停止和卸载都实际点一遍，确认任务真的没了（Mac `launchctl list | grep biqi`，Windows `Get-ScheduledTask -TaskName "碧琪-*"`）。
- 回复里分清：哪些已实测、哪些因为没权限或用户还没点头只做到了哪一步。
