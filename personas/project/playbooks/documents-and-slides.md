# 打法：PPT、Word、PDF、简历、报告和公文

这类东西的好坏，用户在**别人的电脑上打开、投到屏幕上、打印出来**的那一刻才见分晓：字体被换掉、分页断在标题后面、表格冲出页面，都会让一份内容不错的文档显得很业余。所以这份打法的重点是：**选对格式、排得规范、转成页面图片亲眼看过再交**。

## 一、先定交什么格式

| 用户拿去干嘛 | 交什么 | 怎么做 |
|---|---|---|
| 自己还要改、要交给单位或老师改 | `.docx` / `.pptx` | Word 用 python-docx（或 Node 的 `docx`）；PPT 用 pptxgenjs（或 python-pptx） |
| 发出去给人看、要打印、要投递（简历、通知、报价单） | PDF | 排版要求高的（简历、宣传册、报告封面）用 HTML 排好再用浏览器打印成 PDF，最好看、最好控制 |
| 只是放映、讲完就算 | PDF 或 HTML 幻灯片 | 可以用 Marp、Slidev 或自己写 HTML 幻灯片，再导出 PDF |
| 拿不准 | 两样都给：可编辑原件 + PDF | 一句话说明哪个用来改、哪个用来发 |

单位、学校、甲方给了模板的，**模板优先**，在模板里填内容，不另起一套。论文、标书这类有固定格式要求的，没有模板就问用户要——这是只有用户才有的东西。

工作区 `skills/` 里有做 PPT、Word、PDF 的 Skill 就先读它，照它做；没有就照这份做。

## 二、中文文档的排版底子

- **字号**：正文小四（12pt）或五号（10.5pt）；一级标题三号（16pt）或小二（18pt），层级不超过三级；同级标题样式全文一致。
- **行距和段落**：正文 1.5 倍行距（或固定 20–28 磅），首行缩进 2 字符，段前段后统一。
- **字体**：要发给别人改的 `.docx` 只用对方电脑上一定有的字体——宋体、黑体、微软雅黑、等线、仿宋；Word 文件不带字体，对方没有就会被替换成别的字。PDF 会带上字体，可以用更好看的字体（商用时注意字体授权，免费可商用的有思源黑体、思源宋体、阿里巴巴普惠体等）。
- **python-docx 写中文的坑**：只设 `run.font.name` 不够，中文会退回默认字体，要同时设东亚字体：
  ```python
  from docx.oxml.ns import qn
  run.font.name = "宋体"
  run._element.rPr.rFonts.set(qn("w:eastAsia"), "宋体")
  ```
- **用样式，不手调**：标题用「标题 1/2/3」样式，正文用「正文」样式——这样目录能自动生成，用户以后改起来也整齐。
- **目录**：python-docx 只能插入目录域，页码要在 Word 里更新，交付时告诉用户「打开后在目录上右键 → 更新域」；或者用 LibreOffice 转一遍把页码算好。
- **表格**：表头加粗、底色浅灰；数字右对齐、文字左对齐；跨页的表格设表头重复；表格宽度不超过版心。
- **页面**：A4、页码、必要时页眉；图表有编号和标题（「图 1 …」「表 1 …」）。

**公文（通知、请示、报告）按 GB/T 9704 的常用规格：** 页边距上 37mm、下 35mm、左 28mm、右 26mm；标题二号小标宋体（没有就用宋体加粗代替，并说一声）；正文三号仿宋（Windows 是「仿宋」或「仿宋_GB2312」，Mac 是「华文仿宋」）；每页 22 行、每行 28 字；发文机关和日期右对齐，日期用阿拉伯数字。单位有自己的模板时以模板为准。

**简历：**
- 经验少的一页，最多两页；最近的经历放最前。
- 每条经历一句话写清「做了什么 + 结果」，结果尽量有数字（「三个月把复购率从 12% 做到 19%」）；针对投递的岗位调整关键词。
- 只能润色用户给的事实，**不编经历、不编数字**；缺数字就问用户要，或者写成不带数字的实在描述。
- 国内很多岗位习惯放证件照，外企一般不放——没说就留一个照片位并提一句。
- 交 PDF，文件名「姓名-岗位-简历.pdf」。

**合同、协议：** 可以按用户的情况起草或检查，但第一句说清我不是律师，关键条款（金额、期限、违约、解除）标出来，建议重要合同请专业人士看一眼。

## 三、PPT：一页一个意思

- **先写故事线，再做页面。** 一句话结论 → 3 到 5 个支撑论点 → 每个论点的证据（数据、案例、图）→ 最后一页写要大家做什么。故事线先自己读一遍顺不顺。
- **标题写结论，不写话题。** 「三季度销量涨了 23%，主要靠老客复购」，不是「三季度销量情况」。
- **字少：** 每页正文不超过 6 行、每行不超过 20 个字；放映用的正文不小于 18pt，大会场不小于 24pt；标题 28–40pt。讲的话放进演讲者备注，不堆在页面上。
- **一套到底：** 16:9；标题位置、页边距、配色（一个主色 + 灰）、字体、图标风格全套一致；页码固定在一个角。
- **图比字有力：** 能用一张图、一个大数字、一张对比图说清的，不用三段字。图表一页只讲一个结论，把要说的那一组数据标出颜色，其它变灰（`data-and-charts.md`）。
- **该有的页：** 封面（标题 + 汇报人 + 日期）；超过 10 页加目录或章节页；结尾页写结论或下一步，不写「谢谢观看」就完事。
- **替用户填的内容要标出来：** 用户没给的产品名、价格、配方、数据，可以先按常见情况填上，让页面完整、能直接讲，但页面上用【】括起来，交付第一段说清「【】里是按常见情况写的示例，换成你们真实的」。没括起来的只能是用户给过的事实。
- **避开一眼 AI 味：** 每页一个 emoji、三列卡片配渐变、每段都有小标题、满屏「赋能」「助力」。
- **字体：** 用放映那台电脑一定有的字体（Windows 上的微软雅黑、等线）；用了特别的字体就同时交一份 PDF 备用，免得到现场字体被换。

**pptxgenjs 最小骨架**（项目里 `npm install pptxgenjs --registry=https://registry.npmmirror.com`）：
```js
const pptxgen = require("pptxgenjs");
const pptx = new pptxgen();
pptx.layout = "LAYOUT_16x9";
const s = pptx.addSlide();
s.addText("三季度销量涨了 23%", { x: 0.6, y: 0.4, w: 8.8, h: 0.8, fontFace: "Microsoft YaHei", fontSize: 32, bold: true, color: "1F2328" });
s.addNotes("这里写要讲的话");
pptx.writeFile({ fileName: "汇报.pptx" });
```

## 四、亲眼验：转成页面图片，一页一页看

文档和 PPT 都要**变成图片看过**才算检查过，只看「文件生成了」不算：

- 有 `look-doc` 就先用它。
- 转 PDF 的几条路（按这台电脑上有什么选，`TOOLS.md` 里检测过）：
  - LibreOffice：`soffice --headless --convert-to pdf 文件.docx`（PPT 一样）。
  - Windows 装了 PowerPoint / Word：用 PowerShell 调它导出 PDF（PowerPoint：`$a = New-Object -ComObject PowerPoint.Application; $p = $a.Presentations.Open("完整路径", $true, $false, $false); $p.SaveAs("输出完整路径.pdf", 32); $p.Close(); $a.Quit()`）。
  - Mac 有 Keynote：用 `osascript` 让 Keynote 打开 `.pptx` 导出 PDF。
  - 都没有：LibreOffice 将近 1GB，先问用户要不要装；不装就只能检查结构和文字，交付时如实说「排版没转成图片看过」。
- PDF 转图片：`pdftoppm -png -r 60 文件.pdf 页`，或 Python 的 `pdf2image`。用 `read` 一页一页看。
- **看什么：** 有没有方框乱码或字体被换；标题有没有孤零零掉在页底；表格、图片有没有冲出页面；分页、页码、目录对不对；PPT 每页的主角是不是一眼能看到、有没有字挤出边框；整套风格前后是否一致。
- **看的必须是交出去的那个文件。** `.pptx` 和 PDF 分开生成的（比如 PDF 是从 HTML 打印的），两样都要转成图片看；只看了 HTML 版不算看过 `.pptx`。`look-doc` 对 PPT 只出第一页，要看全套先按上面的路转成 PDF。
- 有字数、页数、标题数这类要求的，**真的数一遍**（转文字后数），不凭感觉报。

## 五、示范

**示范一：「帮我做个工作总结 PPT，10 页左右」**（给了一份文字稿）
- 好的做法：从文字稿里提出一句话结论和 4 个论点，排成 10 页的故事线（封面、结论页、4 个论点各 1–2 页、难点和下一步、结尾）→ 标题全部写成结论 → 数据做成图表，要强调的那根柱子上色 → pptxgenjs 生成，字体用微软雅黑 → 转 PDF 再转图片一页页看，发现第 6 页字太多，拆成两页、话挪进备注 → 交付 `.pptx` + PDF，附前 4 页的拼图，说一句「按 16:9 投屏做的，讲稿在每页备注里」。
- 差的做法：每页一个标题加 8 条要点，标题都是「工作概述」「工作内容」「工作亮点」。

**示范二：「帮我改下简历，投产品运营」**
- 好的做法：读原简历 → 按产品运营岗重排：最相关的经历放前面，每条改成「做了什么 + 结果」，原简历里没有数字的地方用 `ui` 表单一次问齐（「活动拉了多少人」「转化率大概多少」）→ 用 HTML 排成一页打印成 PDF → 转图片看一遍对齐和留白 → 交付 PDF + 可改的 `.docx`。
- 差的做法：自己编一个「转化率提升 300%」。*差在哪：* 简历里的假数字，面试一问就穿帮，害的是用户。

**示范三：「写个放假通知，按公文格式」**
- 好的做法：按 GB/T 9704 常用规格出 `.docx`（标题、主送机关、正文、落款、日期）→ 这台电脑没有小标宋，用宋体加粗代替并在交付时说明 → 转 PDF 看版心和行数 → 交付。
