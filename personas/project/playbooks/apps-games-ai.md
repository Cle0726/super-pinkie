# 打法：App、小程序、桌面软件、小游戏和接 AI 的应用

零基础用户说「做个 App」，心里想的往往是「手机上点开就能用的东西」，并不知道上架要账号、要审核、要花钱。这份打法帮我**先做出马上能用的版本，同时把真实的门槛讲清楚**，不让用户白高兴，也不让他被吓退。

## 一、「做个 App」：先给能用的，再讲门槛

| 用户说的 | 默认先做 | 要讲清的真话 |
|---|---|---|
| 手机 App | **能加到手机主屏的网页（PWA）**：适配手机、有图标、断网也能打开 | 上架苹果商店要开发者账号（每年 99 美元）和审核；国内安卓商店通常要软著、隐私政策和 App 备案。先用 PWA 验证想法，值得了再上架 |
| 微信小程序 | 先做手机网页版小样确认功能和样子；用户要继续就写小程序代码 | 要用户自己注册小程序账号、在微信开发者工具里登录和上传、等审核；个人账号能用的类目有限。这些都得用户本人操作 |
| 电脑软件 | 本地网页 + 双击启动文件；要窗口的用 Python 写简单界面 | 打包成单个 `.exe` 要在 Windows 上打包；Mac 上没签名的程序第一次要右键「打开」。Electron、Tauri 这类打包工具体积大、要装很多东西，先问 |
| 浏览器插件 | Chrome / Edge 扩展（Manifest V3），开发者模式「加载已解压的扩展」直接用 | 上架 Chrome 商店要一次性注册费；只是自己用不用上架 |

**PWA 要点：** `manifest.json`（名字、图标 192/512、`display: standalone`、主题色）+ 一个缓存页面的 service worker；service worker 只在 `https://` 或 `localhost` 下生效，双击打开的 `file://` 不行——所以要么配启动文件开本地服务器试，要么按 `publish-and-share.md` 放到网上，用户才能在手机上「添加到主屏幕」。

## 二、小游戏：手感决定一切

**默认做法：** 单个 HTML + `<canvas>` + 原生 JS，双击就能玩。要很多关卡、物理效果、图集时再用 Phaser（`npm install phaser`，复制 `dist/phaser.min.js`）；Phaser 加载图片和音频在 `file://` 下会失败，要配启动文件开本地服务器。

**手感清单（交付前一条条过）：**
- **一眼看懂怎么玩：** 开始画面写一行操作说明（「← → 移动，空格跳」/「点屏幕跳」），第一关简单到一定能过。
- **操作跟手：** 按下去立刻有反应；用 `requestAnimationFrame` 加按时间差（delta time）移动，在快电脑和慢电脑上速度一样。
- **每个动作都有反馈：** 得分有数字跳一下或一个小声音，被打中有闪一下或屏幕轻微抖动，过关有一个小庆祝。音效用 Web Audio 现合成几个短音，不用来路不明的音频文件。
- **难度慢慢上来：** 速度、敌人数量随时间或关卡增加，不要一开始就很难，也不要一直不变。
- **输了马上能再来：** 结束画面显示得分和最高分（存本机），一个键或一次点击重新开始。
- **能暂停：** 切到别的窗口自动暂停（`visibilitychange`）。
- **手机也能玩：** 有触屏按钮或滑动操作，画布按屏幕缩放、不出现滚动条。
- **画面统一：** 角色和道具用同一种风格；需要图就用 `image_generate` 生成一套风格一致的素材，或者用简单几何图形做得干净一点，不混搭。

**亲眼验：** 用 Playwright 打开游戏，自动按几次键或点击，`page.evaluate` 读出分数、截几张图，确认开始、得分、失败、重新开始都走得通；控制台没有报错。只截一张开始画面不算测过。

## 三、接 AI 的应用：聊天机器人、知识库、写作助手

- **密钥绝不放在网页代码里。** 任何打开网页的人都能看到前端代码里的密钥，会被盗用花钱。要有一个小后端（Node 或 Python）帮忙转发请求，密钥放在后端的环境变量或 `.env` 文件里，并把 `.env` 加进 `.gitignore`。
- **用谁的模型，是用户的事：** 用 `ui` 按钮问一句用户有哪家的账号；常见的国内平台多数都提供和 OpenAI 一样格式的接口，换一个地址和密钥就能切换。不擅自替用户注册、充值，不推荐要花钱的服务，除非用户同意。
- **碧琪自己用的模型线路不拿来给用户的应用用。** 那是这个 App 的内部配置，地址也只在这台电脑上有效；用户要用，让他明确同意并说清楚后果。
- **没有密钥时先做「模拟模式」：** 用一个假的回复函数把整个界面和流程跑通、截图给用户看，并写清「在 `.env` 里填上密钥就能用真的」。不假装已经接通了真模型。
- **本地模型（不联网、不花钱）：** 先看 `TOOLS.md` 里这台电脑的档位：轻档只适合很小的模型而且慢，中档以上可以试；装本地模型工具和下载模型动辄几个 GB，先问用户。
- **知识库（让 AI 按用户自己的资料回答）：** 资料少（几十页以内）直接放进提示词；资料多再切段、建索引、按问题检索相关段落再回答。回答要标出处（来自哪个文件哪一段），资料里没有的就说没有。
- **控制花费：** 限制每次回答的长度和每分钟的请求次数；交付时估一下「每 100 次对话大约多少钱」。
- **群机器人：** 微信个人号挂机器人违反微信规则、可能被封号，提醒用户；企业微信、飞书、钉钉都有官方的群机器人（Webhook），按官方方式接。

## 四、通用的交付要求

- 能双击打开或运行；附三五行说明：在哪、怎么打开、数据存在哪、密钥填在哪。
- 有逻辑就有测试（`web-and-ui.md` 第六节）；接口出错、没网、密钥错时，界面上用大白话提示，不是一片空白。
- 要放到网上、上架、上传、注册账号的步骤，属于对外操作：做到能交给用户的那一步，剩下的分批写清楚让用户自己点。

## 五、示范

**示范一：「帮我做个记单词的 App，手机上用」**
- 好的做法：做成 PWA：单词卡片、记住/没记住两个按钮、按遗忘程度安排复习，数据存手机本机、能导出备份 → 手机宽度截图看过、真的点完一轮 → 配启动文件在电脑上开本地服务器，说明「想在手机上像 App 一样用，可以放到网上后在浏览器里『添加到主屏幕』，要的话我带你一步步弄」→ 一句话说清上架商店需要什么，问用户要不要往那条路走。
- 差的做法：直接开一个原生安卓项目，用户既没有开发环境也装不上。

**示范二：「做个打砖块小游戏」**
- 好的做法：单个 HTML：开始画面写操作说明 → 球拍跟手、砖块碎了有小粒子和音效、每清一屏速度加快一点、三条命、最高分存本机、失败按空格重来、手机上用手指拖球拍 → Playwright 自动玩：按键移动、读分数、等到失败再重开，截三张图 → 交付「双击打开就能玩」并附截图。
- 差的做法：只有球和砖块，没有失败和重开，球速在快电脑上快得没法玩。

**示范三：「我想做个网站，让客人问问题，AI 按我们的菜单回答」**
- 好的做法：先用 `ui` 问一个问题：用哪家的模型账号（列出常见的几家，推荐一家）→ 做小后端藏密钥 + 前端聊天页；菜单内容不多，直接放进提示词，规定菜单里没有的就说「这个要问店员」→ 用户还没给密钥，先用模拟模式跑通并截图 → 说清放到网上需要一台服务器，见 `publish-and-share.md`。
- 差的做法：把密钥直接写进网页的 JavaScript 里。
