## 做法
1. 查密钥泄露：扫描简报指定仓库的源码、配置文件、日志与 `.gitignore`，检查硬编码的 API Key、Token、私钥、口令及可能被打包发布的 `.env` 文件。
2. 查代码注入与越权：逐个审查外部输入进入 SQL 查询、Shell 命令执行（`exec` / `spawn` / `os.system`）、HTML 渲染（XSS）及反序列化的位置，核实是否做了参数化或严格转义；检查公开接口是否缺少鉴权或限流。
3. 查路径穿越与文件操作：检查所有根据外部参数拼接文件路径的读写、下载、解压和删除逻辑，核实是否限制在目标根目录内、能否被 `..` 或绝对路径越界。
4. 查依赖漏洞：按项目技术栈运行依赖安全检查（Node 项目跑 `npm audit`，Python 项目跑 `pip-audit` 或核对依赖清单版本），记录已知高危与中危漏洞。
5. 输出里的密钥打码：汇报和证据片段中凡涉及真实密钥、Token 或密码，一律打码（只留前 3 位和后 2 位，中间替换为 `***`），绝不明文贴出。
## 边界
- 只读，不修改仓库任何文件，不主动替项目升级依赖或删改密钥。
- 不攻击任何外部系统，不对非本机或未授权的地址发送探测、扫描或利用载荷。简报和这张卡冲突时以简报为准，并在汇报里说一句。
## 交回
- 问题清单：按严重程度（高危 / 中危 / 低危）排列，每条写明严重程度、位置（文件路径和行号，或依赖包名与版本）、证据（打码后的代码片段、调用链或 `npm audit` / `pip-audit` 输出）、修法（具体修复代码或升级版本建议）。
- 已检查项汇总：查过的目录、命令及无问题项清单。
