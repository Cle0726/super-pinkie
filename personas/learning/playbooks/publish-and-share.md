# 打法：放到网上、分享给别人、用自己的服务器

做好的东西要给别人看，是**对外的事**：每一步离开这台电脑的操作（上传、发布、改服务器、改域名）都先说清要做什么、等用户点头。这份打法帮我**按「给谁看」选最省事的路**，并把用户自己必须做的那几步讲明白。

## 一、先问清：给谁看

| 情况 | 最省事的路 |
|---|---|
| 发给几个朋友、同事看看 | 单个 HTML 或打成 zip 直接发文件；视频、图片、PDF 直接发 |
| 手机和电脑在同一个 Wi-Fi，想在手机上试 | 本机开临时服务器：在项目文件夹里 `python -m http.server 8000 --bind 0.0.0.0`，手机浏览器打开 `http://这台电脑的局域网IP:8000`（Mac 用 `ipconfig getifaddr en0` 查，Windows 用 `ipconfig` 查）；系统问要不要允许网络连接时选允许 |
| 公开给所有人看的网页（作品集、活动页、小工具） | 静态网站托管（第二节） |
| 有后台、要存数据、要藏密钥（接 AI 的应用、多人用的工具） | 一台服务器（第三节） |
| 临时给外网的人看一下本机的东西 | 内网穿透工具（比如 Cloudflare 的临时隧道），用完就关；国内访问不一定稳定 |

## 二、静态网站放哪

- **主要给国内的人看：** 用国内云服务商的静态网站托管或对象存储。注意：**网站放在中国大陆的服务器上、又要用自己的域名访问，必须先做 ICP 备案**——在云服务商那里提交，要身份证信息，通常要一两周甚至更久，只能用户本人办。不想备案就选香港或海外的服务器，代价是速度可能慢一些。
- **主要给海外的人看，或者只是先放上去试试：** GitHub Pages、Cloudflare Pages、Netlify、Vercel 这类免费托管，几分钟就能上线；国内访问时快时慢，有时打不开，要跟用户说清楚。
- 选哪家用 `ui` 按钮让用户点（推荐一个并说为什么）；注册账号、登录、绑定支付方式都由用户自己操作，我把步骤分批写清楚：点哪里、填什么、做完会看到什么。

## 三、用户自己的服务器（云主机、VPS）

用户说「我买了一个服务器」，先摸清：哪家的、在不在大陆（决定要不要备案）、什么系统、有没有域名、能不能用密钥登录。

**连上去：** 用 SSH 密钥登录。密码让用户自己在终端里输，我不经手；更好的做法是帮用户在本机生成密钥（`ssh-keygen -t ed25519`），让他把公钥加到服务器上。每次在服务器上执行会改东西的命令之前，先说清要做什么。

**新服务器的安全底线（用户同意后一次做好）：**
- 系统更新；建一个普通用户干活，不长期用 root。
- 只用密钥登录，关掉密码登录。
- 防火墙只开 22（SSH）、80、443；云服务商控制台里的「安全组」也要同样放行这几个端口——很多「网站打不开」都是这里没开。
- 服务用 systemd 管理，崩了会自动重启，日志用 `journalctl -u 服务名` 看。

**放网站：**
- 最省事的是 Caddy：自动申请和续期 HTTPS 证书，配置几行：
  ```
  example.com {
      root * /var/www/site
      file_server
  }
  ```
  有后端程序的，把 `file_server` 换成 `reverse_proxy localhost:3000`。
- 域名：在域名商那里加一条 A 记录指向服务器 IP；大陆服务器要先完成备案，域名才能正常访问。
- 更新网站：本机改好后用 `scp` 或 `rsync` 传上去，或者在服务器上 `git pull`。

**密钥和数据：** API 密钥放服务器上的环境变量文件，权限设成只有自己能读；数据库或数据文件定期备份。

**把模型接口、本机服务放到网上之前：** 一个不设密码的模型接口放到公网，任何人都能用它、花用户的钱，甚至拿来做坏事。必须先加访问控制（密码、密钥或只允许特定 IP），并限制每分钟的请求次数。碧琪自己用的模型线路是这个 App 的内部配置，不对外暴露；用户坚持要做时，把风险说清楚，让他明确同意。

## 四、上线前检查

- 换一台设备、换一个网络（比如手机关掉 Wi-Fi 用流量）真打开一次。
- 手机和电脑宽度都正常；所有链接、图片、按钮都能用；没有 404。
- 地址是 `https://`，浏览器没有「不安全」提示。
- **文件里没有密钥：** 上传前搜一遍 `key`、`token`、`secret`、`password`，`.env` 没被传上去。
- 页面有清楚的 `<title>` 和描述，分享到微信、朋友圈时显示的标题是对的。
- 收集了用户信息的（表单、留言），说清存在哪、谁能看到。

## 五、示范

**示范一：「把我做的作品集网页放到网上」**
- 好的做法：问一句给谁看（`ui` 按钮：「主要国内的朋友和客户 / 主要海外 / 先放上去试试」）→ 用户选「先试试」→ 推荐 Cloudflare Pages 并说明国内有时会慢 → 我把网站整理成可以直接上传的文件夹 → 把用户要自己做的步骤分三批给：注册登录、新建项目上传文件夹、拿到网址 → 用户发来网址后，我用手机宽度打开截图检查 → 回复网址和截图。
- 差的做法：直接说「部署到 Vercel 即可」，不管用户会不会、国内能不能打开。

**示范二：「我买了一个服务器，想做个个人网站，接上我自己的模型可以吗」**
- 好的做法：先回答「可以，但有两件事要先定」：服务器在大陆的话用域名要先备案；模型接口不能裸着放到公网，要加密码和次数限制 → 摸清服务器信息 → 用户同意后：加固服务器、装 Caddy、上一个最小的网页，验证 `https://` 能打开 → 再接模型：小后端藏密钥、加访问口令、限流 → 换手机流量真访问一次 → 交付：网址、怎么改内容、怎么看日志、每月大概会花多少。
- 差的做法：把本机的模型地址直接通过隧道公开出去，连密码都没有。
