# 打法：表格、数据分析、图表和看板

用户拿到数据类的成品，最在意两件事：**数字对不对**，和**一眼能不能看出结论**。错一个数，整份东西都不可信；结论埋在一堆数字里，等于没做。

## 一、先看清数据，再动手算

拿到表格（Excel、CSV、从网页抄的）先摸底，不急着出结果：

- 有几张表、多少行、哪些列；每列是什么类型（数字被存成了文字？日期有好几种写法？）。
- Excel 常见的坑：表头不在第一行、表头占两行、合并单元格、合计行混在数据里、隐藏的行列和工作表、单位写在表头里（「金额（万元）」）。
- 空值、重复行、明显的异常值（负的销量、2099 年的日期）——先列出来，不悄悄删；怎么处理写进交付说明。
- 文件编码：中文 CSV 常是 GBK，读的时候试 `encoding="utf-8-sig"`，不行再 `gbk`。

用 pandas 读（`pd.read_excel` 需要 `openpyxl`），先 `df.head()`、`df.dtypes`、`df.isna().sum()`、`df.duplicated().sum()` 看一眼，再决定怎么清洗。

**原文件不动**，清洗和结果都另存新文件（`销售表-整理后.xlsx`）。

## 二、交什么：用户最熟的是 Excel

| 用户要的 | 交什么 |
|---|---|
| 整理、合并、去重、拆分表格 | 新的 `.xlsx`（openpyxl 写），格式整齐 |
| 分析、找原因、看趋势 | 一句话结论 + 3–5 个要点 + 1–3 张图；附上算好的明细表 |
| 以后每个月都要做的报表 | 一个双击就能跑的脚本 + 说明：「把新数据放进这个文件夹，双击它」 |
| 给领导或客户看的 | 一页图文报告（HTML 转 PDF，或 PPT，见 `documents-and-slides.md`） |
| 随时打开看的看板 | 单个 HTML 页面（ECharts），数据从同目录的 Excel/CSV 更新 |
| 在聊天里快速比一比 | 回复里的 `chart` 组件 |

**Excel 交付要像样：** 表头加粗冻结首行、开筛选；列宽按内容调；金额千分位、两位小数，百分比显示成百分比，日期统一格式；用户以后还要改数的地方留公式（`=SUM(...)`），只是结果的地方写值；多张表的给每张表起清楚的名字，第一张放「说明」或汇总。

**数据很大时**（几十万行以上、几百 MB）：先看 `TOOLS.md` 里这台电脑的内存；分块读（`chunksize`），或者用 DuckDB 直接查 CSV，不要一口气读进内存把电脑拖死。

## 三、图表的审美

- **先想图要回答什么问题，再选图：**
  - 比大小 → 横向条形图，从大到小排好。
  - 看趋势 → 折线图（时间在横轴）。
  - 看占比 → 堆叠条形图；饼图只在不超过 5 块时用。
  - 看分布 → 直方图；看两个量的关系 → 散点图。
  - 只有一两个数 → 不画图，直接写大数字。
- **标题写结论：** 「复购客户贡献了 62% 的销售额」，不是「客户类型分析」。
- **只突出一组：** 要说的那根柱子、那条线用主色，其它全用浅灰。
- **直接标数，少用图例：** 数值标在柱子末端，线的名字标在线的末端，读者不用来回对照。
- **不撒谎：** 柱状图的纵轴从 0 开始；不用 3D 图；不用双纵轴（实在要用就把两条轴的颜色和线对应清楚）。
- **少即是多：** 去掉多余的网格线、边框、背景色；颜色一个主色加灰，最多再加一个提醒色；色盲也能分得清（不只靠红绿区分）。
- **中文不能变方框：** matplotlib 要先设中文字体：
  ```python
  import matplotlib.pyplot as plt
  plt.rcParams["font.sans-serif"] = ["PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "SimHei", "Noto Sans CJK SC"]
  plt.rcParams["axes.unicode_minus"] = False
  ```
  图存成 PNG 时 `dpi=200`，用 `read` 打开看字清不清楚。
- **网页看板用 ECharts**（中文文档全、国内常用）：`npm install echarts --registry=https://registry.npmmirror.com`，把 `echarts/dist/echarts.min.js` 复制到页面旁边引用，能双击打开。手机宽度下图表要能自适应（`window.addEventListener("resize", () => chart.resize())`）。

## 四、数字必须对

- **关键数字用两种方法算一遍：** 比如总额用 `sum` 算一次，再按分组加总核对一次；结果对不上就先查清楚。
- 百分比四舍五入后加起来不是 100% 时，在表下注明「因四舍五入，合计可能不等于 100%」。
- 写清楚口径：时间范围、单位、去没去掉退货、按下单日还是付款日。
- 报给用户的每个数字都要来自这一轮真实的计算结果；没算的不报，数据里没有的不编。
- 推断和事实分开说：「销量下降」是事实，「可能是因为涨价」是推断，要标出来。

## 五、亲眼验

- Excel：用 openpyxl 读回来检查行数、列名、几个关键单元格；有条件的转成 PDF 看一眼（`documents-and-slides.md` 第四节），看格式和列宽。
- 图：打开 PNG 亲眼看——标题是不是结论、要强调的那组是不是一眼看得到、字有没有重叠或方框。
- 看板：用 `web-and-ui.md` 的截图脚本截桌面和手机两张，看图表有没有被挤扁、控制台有没有报错。

## 六、示范

**示范一：「帮我看看这个销售表，哪个月卖得最好」**（一个 Excel）
- 好的做法：读表，发现表头在第 3 行、最后一行是「合计」、有 4 行重复订单 → 去掉合计行和重复行，回复里说清 → 按月加总，再用逐行累加核对一次 → 回复：「**卖得最好的是 7 月，38.6 万**，比第二名 5 月多 12%。表里有 4 笔重复订单，我没算进去。」附一张按月的条形图（7 月上主色），另存一份整理好的表。
- 差的做法：直接 `sum` 全表，把「合计」行也加了进去，报了一个翻倍的数。

**示范二：「每个月都要把十几个门店的表合成一张，太累了」**
- 好的做法：先读两三个门店的表，找出列名不一致的地方（「销售额」「销售金额」），做一张对照表 → 写合并脚本，结果另存、带「来源门店」一列 → 配一个双击运行的启动文件和三行说明「把新表放进『门店表』文件夹，双击『合并.command』」→ 用这个月的数据真跑一遍，核对总行数等于各表行数之和 → 交付。
- 差的做法：手动合并这一次，下个月用户还得再来问一遍。
