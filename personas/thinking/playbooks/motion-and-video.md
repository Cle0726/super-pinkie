# 打法：视频、动画、配音、字幕和 3D

用户要的是**能直接发出去的成片**：节奏舒服、字看得清、声音干净、尺寸对平台。这份打法管从点子到导出的整条路：**定规格 → 脚本 → 分镜 → 样片 → 成片 → 声音 → 导出 → 亲眼验**。动手前先看 `TOOLS.md` 里「这台电脑」那一段，没有就按 `machine.md` 测一下——渲染是最吃电脑的活。

## 一、先选做法（按片种，不问用户）

| 用户要的 | 默认做法 | 说明 |
|---|---|---|
| 文字、数据、产品介绍、片头片尾、带字幕的口播包装 | **Remotion**（用代码写画面，渲成 MP4） | 画面精确、改字方便。个人和 3 人以下的公司免费，更大的公司商用要买授权，用户要商用时提一句 |
| 讲道理、数学、原理图解动画 | **Manim** | 中文用 `Text(..., font=中文字体)`；没装 LaTeX 时 `MathTex` 用不了，公式改用 `Text` 或先做成图片 |
| 剪现有素材：剪短、拼接、加字幕、配乐、调色、转格式 | **FFmpeg** | 最稳、最快，几乎所有电脑都能装 |
| 口播、录屏剪掉停顿和空白 | **auto-editor**（按需 `pip install auto-editor`）+ FFmpeg | 先剪静音再加字幕；参数以 `auto-editor --help` 为准 |
| 一组照片做成片（相册、回顾、带推拉的图文） | FFmpeg（`zoompan` 推拉）或 Remotion | 照片先放大再推拉，画面才不抖 |
| 故事短片、MV、「AI 视频」 | 分镜关键画面用 `image_generate` 生成 → 加推拉和视差 → 配音 + 音乐 + 字幕（动态图文片） | 真正「会动的 AI 视频」要用外部的视频生成服务，多半要花钱：先问用户，可以先把每一镜的提示词写好 |
| 网页里的动效、交互动画 | 简单的用 CSS 过渡；有先后顺序的时间线用 **GSAP**（免费，含插件）或 Anime.js | 库下载进项目（见第六节），不用国外 CDN |
| 3D：可转动的产品、3D 场景网页 | **Three.js**；照片级的渲染图或片子用 Blender 命令行（重档电脑才默认用） | 模型优先用户给的 `.glb`；网上模型看授权 |
| 数据动画、会动的图表 | 网页用 D3 或 ECharts；要成视频就在 Remotion 里画 | 数字必须来自真实数据 |
| GIF、表情动图 | FFmpeg 调色板两步法（第七节） | 先问要放在哪：微信、网页还是 PPT，尺寸和大小限制不同 |

工作区 `skills/` 里有对口的视频、动画 Skill（Remotion、Manim、剪辑之类）就先完整读它，照它做；没有就照这份做。

## 二、规格：没说的按这些默认值定，交付时写一句

- **平台和画幅**：没说就按抖音、视频号、小红书的竖屏 1080×1920、30 帧；说了 B 站、YouTube、投影、官网就横屏 1920×1080。
- **时长**：短视频没说就 15–30 秒；故事片按用户说的；讲解动画按内容，一个知识点 30–90 秒。
- **声音**：有台词就配音（第五节），没说要不要音乐就配轻音乐垫底，并说明来源能不能商用。
- **规格按电脑档位**：轻档成片默认 720p（要 1080p 先实测估时），样片一律低分辨率。

## 三、流程关卡：每一关都有能看的东西

1. **脚本**：写成三栏表——画面 | 台词或字幕 | 时长。短视频开头 1–2 秒必须有钩子（先给结果、抛一个问题、或者一个反差画面）。
2. **配音先行**：有台词就先生成配音，用配音的真实长度定每一镜的时长，而不是先定时长再硬塞台词。
3. **分镜图**：每一镜一张关键画面（生图，或者渲染这一镜的某一帧），拼成一张分镜总图自己先看：主角、构图、色调前后一致吗？
   - **超过 1 分钟的片子、故事片、给客户的片子**：把分镜总图给用户看一眼再往下做——这时改方向几乎不花成本。
   - 30 秒以内、方向明确的：直接往下做。
4. **样片**：低分辨率（480p 或 540p）、低帧率先渲一遍整片，看节奏、对口型、字幕时间。
5. **成片**：确认后再出高清，放后台渲，记下日志在哪；这期间去做封面和声音。
6. **声音**：配音、音乐、音效混好，统一响度（第五节）。
7. **导出**：按平台的预设导出（第七节），再做一张封面。
8. **亲眼验收**：第八节，过了才交。

## 四、动起来好看：动效的审美

- **一个时刻只有一个主角在动。** 其它元素静止或只轻微地动；三个东西同时飞进来，眼睛不知道看哪。
- **进场减速、出场加速。** 进场用 ease-out（比如 `cubic-bezier(0.22, 1, 0.36, 1)`），出场用 ease-in，从 A 移到 B 用 ease-in-out。除了匀速滚动和旋转，不用 linear——匀速的东西看起来像机器。
- **时长有档：** 界面上的反馈 150–250ms；元素进场 300–500ms；画面转场 400–700ms。慢于这个就拖沓，快于这个看不清。
- **错开出场：** 一组元素依次进场，每个间隔 40–80ms；逐字出现每字 20–40ms。全部同时出现显得死板，间隔太长显得磨蹭。
- **停得够久：** 屏幕上的大字至少停留「字数 ÷ 5 + 1 秒」；字幕每秒不超过 7–9 个字，竖屏每行不超过 14–16 个字，超了就拆句。
- **回弹要省着用。** 弹性、过冲只给活泼风格的一两处关键动作，幅度不超过 5%；正经内容不弹。
- **镜头慢慢动。** 推拉一镜内缩放 5–10% 就够；不同时推、转、移。
- **转场默认硬切。** 叠化只用来表示时间过去；旋转、翻页、百叶窗这类花哨转场不用。
- **剪辑跟着内容和音乐走。** 短视频每镜 1.5–4 秒，切在音乐的重拍或一句话说完的地方；情绪片可以给长镜头。
- **同一类东西同一种动法。** 所有标题同一种进场，所有数字同一种跳动，统一了才显得有设计。
- **竖屏安全区：** 上方约 8%、下方约 20%、右侧约 12% 常被平台的按钮、昵称和文案盖住，字和主角别放进去。
- **字要清楚：** 竖屏字幕字号不小于 48px（按 1080 宽算）；白字加细黑描边或半透明深色底；中文必须指定中文字体，不然会变方框。
- **网页里的动效：** 只动 `transform` 和 `opacity`；不在闲着时循环播放；尊重系统的「减少动态效果」设置（`prefers-reduced-motion`）。

## 五、声音：配音、字幕、音乐、混音

**配音（按这个顺序选）：**
- 免费、效果好、要联网：`edge-tts`（`pip install edge-tts`）。
  `edge-tts --voice zh-CN-XiaoxiaoNeural --rate=+5% --text "台词" --write-media voice.mp3 --write-subtitles voice.srt`
  常用声音：`zh-CN-XiaoxiaoNeural`（女，温暖）、`zh-CN-XiaoyiNeural`（女，活泼）、`zh-CN-YunxiNeural`（男，年轻）、`zh-CN-YunjianNeural`（男，有力）；全部列表 `edge-tts --list-voices`。它会顺带写出字幕时间轴；格式不是 SRT 时用 FFmpeg 转一下，再把过短、过长的行重新断句。它用的是微软的在线服务：报 403 之类的连接错误时，先 `pip install -U edge-tts` 升到最新版再试（微软会改接口，旧版本会突然失效）；用户要大量商用时提醒一句。
- 断网时的退路：Mac `say -v Tingting -o voice.aiff "台词"`（先 `say -v '?' | grep zh` 看有哪些中文声音）；Windows 用系统自带的中文语音：
  `Add-Type -AssemblyName System.Speech; $s = New-Object System.Speech.Synthesis.SpeechSynthesizer; $s.SelectVoice('Microsoft Huihui Desktop'); $s.SetOutputToWaveFile('voice.wav'); $s.Speak('台词'); $s.Dispose()`
- 要更有感情的配音：付费的云端配音服务，或者在重档电脑上跑本地开源配音模型（几个 GB）。两种都先问用户。

**给已有的视频配字幕（语音转文字）：**
- Apple 芯片的 Mac：`pip install mlx-whisper`，然后 `mlx_whisper 音频.mp3 --model mlx-community/whisper-large-v3-turbo --language zh --output-format srt`（轻档且可用内存不到 3GB 时换 `whisper-small`）。
- 其它电脑：`pip install faster-whisper`，轻档用 `small`、中档 `medium`、重档 `large-v3`：
  ```python
  from faster_whisper import WhisperModel
  model = WhisperModel("small", device="auto", compute_type="int8")
  segments, _ = model.transcribe("音频.wav", language="zh", initial_prompt="以下是普通话的句子，使用简体中文和标点。")
  ```
  再把 `segments` 的起止时间和文字写成 SRT。
- 国内下载模型慢：先设环境变量 `HF_ENDPOINT=https://hf-mirror.com`。
- 识别出繁体时：提示词里写明简体，或者用 `opencc` 转简体。人名、专有名词识别完对一遍，必要时做一张替换表。
- 先用 30 秒的片段试跑量时间，再决定整段用多大的模型（`machine.md` 第四节）。

**音乐：**
- 来源要说得清：用户自己的、明确写着免费可商用的曲库、或者生成的。不从网上扒流行歌。
- 发抖音、视频号这类平台时，另一条路是成片不带音乐，让用户在平台里从它的曲库加——版权最省心。交付时提一句。

**混音：**
- 有人声的地方，音乐比人声低 15–20dB；只有音乐的段落可以抬起来；开头结尾淡入淡出 0.5–2 秒。
- 人声出现时自动压低音乐（ducking）：
  `ffmpeg -i voice.wav -i music.mp3 -filter_complex "[0:a]asplit=2[v1][v2];[1:a]volume=0.6[m];[m][v1]sidechaincompress=threshold=0.03:ratio=10:attack=20:release=400[md];[v2][md]amix=inputs=2:duration=first:normalize=0[a]" -map "[a]" mix.wav`
- 最后统一响度：`-af loudnorm=I=-14:TP=-1.5:LRA=11 -ar 48000`（短视频平台 -14 到 -16 LUFS 都合适；`-ar 48000` 不能省，不然会输出 192kHz 的怪采样率）。
- 音效少而准：只在动作发生的那一帧配，同一类动作用同一个声音。

## 六、在网页里用动画和 3D 库

- **下载进项目，不用国外 CDN**（国内常打不开）：`npm install gsap three d3 echarts --registry=https://registry.npmmirror.com`，再把用到的文件复制到页面旁边。
  - 能直接 `<script src>` 双击打开的：`gsap/dist/gsap.min.js`、`d3/dist/d3.min.js`、`echarts/dist/echarts.min.js`。
  - Three.js 新版本只有模块写法，双击打开的 `file://` 页面加载不了模块：要么配 `web-and-ui.md` 里的启动文件开本地服务器，要么用 esbuild 打成一个普通脚本：`npx esbuild main.js --bundle --format=iife --outfile=bundle.js`，页面引用 `bundle.js` 就能双击打开。
- **Three.js 做产品展示：** `.glb` 模型 + `OrbitControls` 转动 + 环境光照（`RoomEnvironment`）+ `ACESFilmicToneMapping`；`renderer.setPixelRatio(Math.min(devicePixelRatio, 轻档 1.5，否则 2))`；阴影只给主角；页面不可见时暂停渲染。
- **检查流畅度：** 用 Playwright 打开页面跑几秒，在页面里用 `requestAnimationFrame` 数一下帧率；掉到 30 以下就减面数、关阴影、降像素比。

## 七、导出预设

- 通用 MP4（各平台都收）：
  `ffmpeg -i 输入 -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p -r 30 -c:a aac -b:a 192k -ar 48000 -movflags +faststart 成片.mp4`
- 赶时间出样片：有硬件编码就用（Mac `h264_videotoolbox`，NVIDIA `h264_nvenc`，Intel `h264_qsv`，`TOOLS.md` 里检测过），成片仍用 `libx264`。
- 剪片段要精确：`-ss 开始 -to 结束` 放在 `-i` 后面并重新编码，不用 `-c copy`（会从关键帧切，前后不准）。
- 烧字幕：在字幕文件所在的文件夹里运行，`-vf "subtitles=字幕.srt:force_style='FontName=字体名,FontSize=字号,Outline=1'"`，字体按系统选（Mac `Hiragino Sans GB` / `PingFang SC`，Windows `Microsoft YaHei`）。Windows 上把带盘符的完整路径写进 `subtitles=` 很容易出错，用相对文件名最稳。
- GIF：`ffmpeg -i 输入 -vf "fps=12,scale=480:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" 动图.gif`；体积超了就降帧率或尺寸。
- 封面：选最有冲击力的一帧，或者单独做一张（`images-and-print.md`），字放在安全区里。

## 八、亲眼验收（不看不交）

1. **看画面：** 有 `look-video` 就用；没有就 `ffprobe` 拿到时长 D 秒，`ffmpeg -i 成片.mp4 -vf "fps=9/D,scale=360:-1,tile=3x3" -frames:v 1 抽帧.png`，用 `read` 打开亲眼看：主角清不清楚、字有没有方框乱码或被挡住、颜色前后一致吗、有没有黑帧和穿帮。
2. **看开头：** 单独抽第 0、1、2 秒三帧——开头 2 秒能不能让人停下来？
3. **看字幕：** 抽几个换句的时间点，确认字幕和配音对得上、没有一行太长。
4. **听声音：** `ffmpeg -i 成片.mp4 -af loudnorm=print_format=summary -f null -` 看整体响度在 -14 到 -16 LUFS 附近、峰值不超过 -1；没有声音、只有一边声道、爆音都要修。
5. **对规格：** `ffprobe` 核对分辨率、帧率、时长、有没有音轨，和第二节定的一致。
6. 交付：成片路径 + 抽帧图（`MEDIA:` 附图）+ 一句话说清用了什么配音、音乐和画面（生成的、用户给的、还是图库下载的）、能不能商用、我替用户定了什么。给用户自家产品做的片子用了图库照片，画面里是别人家的东西，要直说「画面是图库里的普通拿铁，换成你们店的实拍再发」；介绍画面只写抽帧里真看到的。

## 九、示范

**示范一：「帮我做一条 30 秒的新品宣传视频」**（没说平台）
- 好的做法：按竖屏 1080×1920、30 秒定 → 看 `TOOLS.md`：轻档 → 写三栏脚本，开头 1 秒先亮出产品最打动人的一点 → edge-tts 生成配音，量出 27 秒，按句子定每镜时长 → 每镜一张关键画面拼成分镜图自己看一遍 → Remotion 先渲 480p 样片，看节奏，发现第 3 镜字幕停留不够、拆成两句 → 渲 1 秒量时间，估出 720p 成片约 8 分钟，放后台 → 混音、统一响度 → 抽 9 帧拼图看，发现结尾店名压在平台按钮的位置，上移 → 交付：成片 + 抽帧图 +「按抖音竖屏做的，配音是晓晓，背景音乐来自免费可商用曲库」。
- 差的做法：交一份分镜脚本，说「您可以用剪映按这个分镜制作」。

**示范二：「我想做一个 4 分钟左右的爱情故事视频」**
- 好的做法：先给 3 个真不同的故事走向，推荐一个 → 写分场脚本和旁白 → 写一份人物设定（长相、服装、配色），每张关键画面都带着它生成，保证同一个人前后长得一样 → 先出 12 张关键画面的分镜总图给用户看（4 分钟的片子，方向错了返工最贵）→ 用户点头后：配音 → 每镜加慢推拉和轻微视差 → 音乐 + 字幕 → 先出整片低清样片 → 再出成片。并说清：「这是动态图文的做法，画面会推拉但人物不会真的走动；要人物真的动起来，需要外部的视频生成服务，要花钱，我可以先把每一镜的提示词备好。」
- 差的做法：直接生成 60 张互不相干的图硬拼起来，人物每张长得都不一样。

**示范三：「把这段口播剪干净，加上字幕」**
- 好的做法：`auto-editor` 剪掉停顿（留 0.2 秒余量，听一遍不跳）→ 先用 30 秒试跑语音识别量时间，再整段识别出字幕 → 对一遍人名和专有名词 → 按每行不超过 16 个字重新断句 → 烧进画面，统一响度 → 抽帧检查字幕位置和字体 → 交付成片，另附一份 SRT 方便用户自己改字。
