# 设计 S6：多会话并行看板——一屏看所有在跑的会话

> 队列 17（#96，win-coord 派给 linux3）。出处 `build/quick-run/对比-主流-Metre-1124.md` 第 115 行：「多会话并行看板：一屏看所有在跑的（`sessions.list`）」。
> 该文件在 `build/`（被 `.gitignore` 忽略），本机各工作区都没有，口径以 #96 里 win-coord 的原话为准：写清数据从哪来（轮询还是事件）、每行显示什么（模式、在做什么、卡在等你、用量）、点进去怎么跳、上限多少个、Metre 和碧琪两种皮怎么各自呈现。
> 本稿只是设计，不含代码。win-coord 在本 PR 回「可以做」之后才动手。

## 〇、现在有什么、缺什么

下面的接口都在本仓库里核对过（网关部分看的是裁剪 dist `desktop/windows/mac-runtime/openclaw/dist/`，19 个文件，不是完整源码）。

**网关有的：**

| 接口 | 位置 | 用途 |
|---|---|---|
| `sessions.list` | `sessions-UcKjjh_n.js:433` | 会话列表。每行已带 `hasActiveRun`（布尔）和在跑时的 `activeRunIds`（:461-470），碧琪补丁还加了 `contextTokens` / `pinkieCompactionBudget` / `pinkieContextBreakdown`（:477-480）。界面里已在用的字段：`key`、`label`、`displayName`、`derivedTitle`、`updatedAt`、`status`、`spawnedBy`、`kind`、`totalTokens`、`inputTokens`、`outputTokens`、`lastMessagePreview`（要 `includeLastMessage`，见 `laolao-session-list.js:51`）。 |
| `sessions.subscribe` / `sessions.unsubscribe` | 同文件 :532 / :537 | 按连接订阅会话事件。侧栏连上网关时已经自动订阅（`laolao-sidebar.js:136-137`），看板不用再订一次。 |
| `sessions.changed` 事件 | 由 `emitSessionsChanged` 发（来自 `session-change-event-*.js`，**这个文件不在裁剪 dist 里**）；调用处载荷是 `{sessionKey, reason}`，见到的 reason 有 `send` / `steer` / `cleanup`（:425-429、:522） | 会话增删、开始一轮、被插话。 |
| `session.operation` 事件 | `sessions-UcKjjh_n.js:127-133`，只发给订阅者，`dropIfSlow` | 压缩等操作（`laolao-context-compact.js:571` 在听 `operation === 'compact'`）。 |
| `chat` 事件 | `chat-pg-BxhF6.js` 里 `broadcast("chat", …)` | 一轮的 `delta` / `final` / `error` / `aborted`。 |
| 运行事件流（`stream` 为 `lifecycle` / `tool`） | 界面在 `laolao-metre-perm.js:534-540`、`laolao-session-cards.js:528` 里听 | 一轮开始 / 结束（`data.phase`），工具调用（`data.name` / `data.toolName`）。 |
| `exec.approval.requested` / `plugin.approval.requested` 及 `…resolved` 事件 | 界面在 `laolao-metre-perm.js:526-530` 里听，载荷带 `id`、`request.sessionKey` / `sessionKey`、`request.command` | 「卡在等你」的来源。 |
| `sessions.usage {key}` | `server-methods-NpEcZnvp.js:455`，界面用法 `laolao-metre-perm.js:93`（超时给到 15 秒） | 单个会话的令牌和花费，偏慢。 |

**碧琪已有、可复用的：**

- 事件总线：`laolao-sidebar.js:117-124` 把所有网关事件转成 `pinkie:gateway-event`（只读），`sessions.changed` 和一轮结束另发 `laolao:sessions-changed`。看板只听这两个，不自己碰 socket。
- 请求：`window.__laolaoSidebar.gwRequest(method, params, timeout)`。
- 跳转：`window.__pinkieNativeBridge.openSession(key)`（`laolao-native.js:69`）——跨模式时写好 `laolao:last-session:<mode>` 再带 `laolao-switch=1` 重新载入；同模式走 `window.__laolaoSidebar.navigateSession(key)`（`laolao-sidebar.js:877`，Metre 上了锁会先弹解锁）。系统通知点击（`laolao-run-notify.js:120`）走的是同一条路。
- 模式识别：`laolao-native.js:42-46` 的 `modeOf(key)` 和 `MODE_LABEL`（唠嗑 / 项目 / 想法 / 学习 / 无限制 / Metre）。
- 「在跑」判定：`laolao-native.js:248-250` 已经这样筛：`sessions.list {limit: 1000}`，去掉 `:subagent:`，留 `hasActiveRun` 或 `status` 是 `running` / `queued` 的。
- 状态文案：`laolao-run-status.js:17-30` 的 `PHRASE`（碧琪皮）和 `METRE_PHRASE`（Metre 皮），以及贴纸集 `asking / done / oops / thinking / working / writing`（:237）。
- Metre 总控台：`pinkie.metre.board {sessionKey}`（`services/mode-architecture/metre-board.mjs:459`）只管**一个** Metre 会话和它的子会话（:320-360，每行有 `status`、`doing`、`usage`、`modeName`、`model`），`pending` 里有 `ask_user` 类的等你（:254）。

**没有的（明说）：**

1. **没有「列出所有待批」的接口**：裁剪 dist 里只找到 `exec.approvals.get / set`（放手程度配置，不是待批队列），找不到 `exec.approval.list` 或等价方法。现在 P4 待批汇总是从原生卡片 DOM 读的（`laolao-metre-perm.js:259` `approvalSoon` → `paintApproval`）。所以看板打开前发生的审批请求，看板自己拿不到——见第二节「等你」的处理和第八节待核对。
2. **没有跨会话的「在做什么」**：`sessions.list` 只给在不在跑，不给当前步骤。只能看板开着时从事件流自己拼（第一节）。
3. **没有全局并发上限的配置项**：dist 里只有按 lane 排队的 `maxConcurrent`（`dist/embedded-*.js` 第 2073 行，`getCommandLaneSnapshot`），没找到对外的设置。看板不管「最多同时跑几个」，只管「最多显示几行」（第四节）。
4. `session-change-event-*.js` 不在裁剪 dist 里，`sessions.changed` 的完整载荷本机看不到，上面只写了调用处传的字段。

结论：**不要内核改动，也不要新的插件网关方法**；第一版只用已有接口在界面里拼。

## 一、数据从哪来：事件为主，读列表兜底

| 时机 | 做什么 |
|---|---|
| 打开看板 | 读一次 `sessions.list {limit: 200, includeLastMessage: true}`（不按模式过滤，一次拿全部）。 |
| `laolao:sessions-changed`，或运行事件 `lifecycle` 的 start / end | 合并后重读 `sessions.list`，**每秒最多一次**（和 `laolao-metre-board-data.js` 的节流一致）。 |
| 运行事件 `tool`、`chat` 的 `delta` | **不读列表**，只更新那一行的「在做什么」（内存里一张 `key → doing` 表）。 |
| `exec / plugin.approval.requested` | 那一行标「等你」，记 `id`；对应的 `…resolved` 来了就清掉。 |
| 兜底轮询 | 看板开着、**而且**至少有一行在跑时，20 秒没收到任何事件就主动读一次（同 `laolao-metre-board-data.js` 的看门狗）；什么都没在跑就不发请求。 |
| 看板关着 | 一律不读。侧栏入口上的数字只在 `laolao:sessions-changed` 后读，最多 5 秒一次。 |
| 断线（`pinkie:sidebar-gateway-lost`） | 各行保留上一次的数据并变灰，「在跑」改成「断线前在跑」；连上（`pinkie:sidebar-gateway-ready`）后重读一次，并清空 `doing` 和「等你」表（断线期间可能已经变了，宁可空着也不显示错的）。 |

为什么不纯轮询：`sessions.list` 每次都要读会话库和模型目录（:439-447，三段 diagnostics span），多会话一起跑时每秒轮询太重；事件本来就已经在 `pinkie:gateway-event` 上了，零额外请求。

为什么不纯事件：`sessions.changed` 的完整载荷看不到（〇-4），丢一次就错；所以「开始 / 结束」这种改变行数的事件统一触发重读，列表才是唯一真相，事件只填列表没有的细节。

## 二、每行显示什么

一行只给一个会话，从左到右：

| 列 | 内容 | 来源 |
|---|---|---|
| 状态 | 在跑 / 排队中 / 等你 / 出错 / 刚做完（10 分钟内） | `hasActiveRun`、`status`、「等你」表、`chat` 的 `error` |
| 模式 | 「唠嗑」「项目」「想法」「学习」「无限制」「Metre」小标签 | `modeOf(key)` + `MODE_LABEL` |
| 标题 | `label` → `displayName` → `derivedTitle` → 「新会话」 | `sessions.list` |
| 在做什么 | 见下面的规则，一行截断，悬停看全文 | 事件流 |
| 已用时 | 这一轮开始到现在（`lifecycle` start 的时刻；看板打开前就开始的，写「≥ X 分」并以 `updatedAt` 估） | 事件流 / `updatedAt` |
| 用量 | 上下文占用 `totalTokens / contextTokens`，画一小条，超过 `pinkieCompactionBudget` 的阈值变色 | `sessions.list` |

「在做什么」的规则（纯函数 `describeRow(row, live)`，同样输入同样一行字，测试直接验）：

1. 有「等你」→ **「等你确认：<命令前 40 字>」**，整行用提醒色，排到最上面。命令取 `request.command`；没有就写「等你确认」。
2. 最近一个 `tool` 事件 → 「在用 <工具名>」（工具名照 `laolao-run-status.js` 现有的人话映射，没有映射就原样）。
3. 最近是 `chat` 的 `delta` → 「正在回复」。
4. 在跑但看板打开后还没收到它的事件 → 「在跑」（不猜）。
5. 不在跑 → `lastMessagePreview` 的前 40 字，灰色。

「等你」的局限要写在界面上，不藏：看板打开前就已经在等的审批，事件已经错过、又没有列表接口（〇-1），这类会话只能显示成「在跑」。第一版的补救：看板打开时，当前会话页上原生审批卡片如果在（`laolao-metre-perm.js` 已经读得到），把它对应的会话标成「等你」；其他会话照实显示「在跑」。若核对后找到待批列表接口，改成打开时读一次列表。

不显示花费：`sessions.usage` 单次就要等到 15 秒（`laolao-metre-perm.js:93`），每行都调太重。行内只给令牌；**展开一行**（第三节）时才对这一个会话调 `sessions.usage {key}` 显示花费。

分组和排序：等你 → 在跑 / 排队中（按开始时间，早的在上）→ 出错 → 刚做完。`:subagent:` 子会话不单独占一行，挂在父会话下面缩进显示（父会话由 `spawnedBy` 找），默认收起，父行写「另有 N 个分身在跑」。

## 三、点进去怎么跳

- **点整行**：`window.__pinkieNativeBridge.openSession(key)`，看板随之关闭。
  - 同模式：直接切会话，不重新载入。
  - 跨模式：页面会重新载入到目标模式（现有行为，通知点击同样如此）。行上模式标签和当前模式不同时，悬停提示写「会切到「<模式>」」，免得以为点坏了。
  - Metre 会话上了锁：走 `navigateSession` 现有的解锁弹层，解开后再进；取消就留在看板。
- **点「等你」行**：同上跳过去；跳到后由现有的原生审批卡片接手，看板**不在行里直接给「允许 / 拒绝」**——审批要看全命令和上下文，放在一行里容易误点。第二版若要加，复用 P4 的 `exec / plugin.approval.resolve` 调用（`laolao-metre-perm.js:191`），并且要求先展开看全命令。
- **点子会话**：跳到子会话（照旧只读）。
- **展开（行尾小箭头）**：不跳转，在行下面展开：完整标题、模型、开始时间、令牌明细、花费（此时才调 `sessions.usage`）、最近 3 个工具名。
- **键盘**：↑ / ↓ 换行，Enter 跳转，→ 展开，← 收起，Esc 关看板；打开时焦点在第一行。

## 四、上限多少个

- **读**：`sessions.list` 用 `limit: 200`。超过 200 个会话时只算 `updatedAt` 最新的 200 个；在跑的会话 `updatedAt` 一定是新的，实际不会漏。
- **显示**：「等你 + 在跑 + 排队中 + 出错」**最多 12 行**，超出折成最后一行「还有 N 个在跑」，点开在看板里滚动显示全部（不分页）。「刚做完」最多 5 行，只看 10 分钟内的。子会话每个父行展开后最多 10 个，超出写「还有 N 个」。
- **为什么 12**：1440×900 下看板一屏放得下 12 行不滚动；再多一屏看不全，就不叫「一屏看」了。这个数写成常量，测试里覆盖。
- **不限制同时跑几个**：看板只看不管。并发由网关 lane 自己排队（〇-3）；排队中的显示「排队中」（`status === 'queued'`，同 `laolao-native.js:250` 的判定）。

## 五、两种皮怎么各自呈现

同一份数据和 `describeRow()`，只换外壳和文案。按 `document.documentElement` 的 `data-laolao-mode` 选皮（`laolao-mode-switcher.js:322`），`laolao:modechange` 时重画。

| | 碧琪皮（其余五个模式） | Metre 皮 |
|---|---|---|
| 入口 | 侧栏顶部一个小胶囊「在跑 N」（N=0 时不显示），点开从侧栏右边滑出一块面板 | Metre 总控台里加一栏「全部会话」，和现有九块并列；总控台关着时，侧栏入口和碧琪皮同一个位置但用 Metre 的样式 |
| 状态文案 | 用 `PHRASE`：「碧琪在抛气球干活…」「碧琪在等你点头…」「完成啦！」 | 用 `METRE_PHRASE`：「在处理」「等你确认」「完成」；总状态一句沿用总控台的「N 个声部在奏 / 等你（N）/ 休止」口吻 |
| 每行左侧 | 碧琪贴纸（`working / asking / oops / done`）代替状态点 | 小谱台像素画（`laolao-metre-board-data.js` 里 `REST` 那一套），亮灯 = 在跑 |
| 用量条 | 圆角粉色细条 | 直角细线，和总控台「用量」块同一种画法 |
| 空状态 | 「现在没有在跑的会话」+ 坐着的碧琪 | 没亮灯的谱台 +「这一声部还没开始」（沿用总控台空状态） |
| 区域 | `sidebar` 区域（`REGIONS.md`：侧栏、会话列表） | `metre` 区域（根选择器 `[data-metre-board]` / `.metre-board`） |

和 Metre 总控台「声部」块的关系：声部块只看**当前这一个 Metre 会话的子会话**（`pinkie.metre.board`），不动它；S6 的「全部会话」栏看**所有模式的所有会话**，Metre 会话那一行展开时，直接显示总控台已算好的子会话状态，不重算。

## 七、怎么测

全部在隔离环境，不碰正式 App、`~/.openclaw`、18789。

1. **Node 单元测试** `tests/session-board.test.mjs`（`describeRow()` 和排序是纯函数，不起浏览器）：
   - 五条「在做什么」规则各一例，「等你」压过工具名；
   - 排序：等你 → 在跑 → 出错 → 刚做完；超过 10 分钟的「做完」不出现；
   - 上限：13 个在跑时第 13 个折进「还有 1 个」；子会话挂到父行下、超过 10 个折叠；
   - `approval.requested` 后标「等你」，`resolved` 后清掉，断线重连后清空；
   - 节流：一秒内 10 个 `sessions.changed` 只读一次列表；`tool` 事件不触发读列表；
   - 看门狗：有在跑时 20 秒无事件读一次，没在跑时不读。
2. **真浏览器界面测试** `tests/session-board-ui.test.mjs`（WebKit + Chromium，假网关）：碧琪皮和 Metre 皮各打开一次；点同模式行不重新载入，点跨模式行带 `laolao-switch=1` 载入；Metre 上锁时先弹解锁；键盘 ↑↓ Enter Esc；断线时行变灰、文案改成「断线前在跑」。
3. **复发防护**：「断线不显示成做完」「看板关着不发请求」两条单独成测试，对应 11-15 用户要求「不要后端挂了前端还在转」。
4. 门禁：`node tools/release-gate/run-tests.mjs`、`node --test tests/code-health-ratchet.test.mjs tests/ui-region-ownership.test.mjs tests/visual-baseline.test.mjs tests/hotspot-ui-regression.test.mjs`；不加 known-failures，不动视觉基线（看板默认关着，现有截图不该变）；pr-shots 补两种皮 × 浅 / 深 × 有会话 / 空状态。
