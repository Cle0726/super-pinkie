  - 发送拦截点：`ui/injections/laolao-sidebar.js:180-200`，在 ws 层拦 `chat.send` / `sessions.send` / `sessions.steer`；`:subagent:` 会话已在这里直接回 `INVALID_REQUEST 分身会话只读`；之后进 `sendQueues`，依次 `ensureProjectScope(key)`（:423）→ `__pinkieWorkbench.flushContext` → 查 `abortVersions`；`/` 开头的消息已有单独分支（不进增强推演）。
  - 显示结果：网关 `chat.inject`（`chat-pg-BxhF6.js:4064`），参数 `sessionKey / message / label`，在 `beginSessionWorkAdmission` 下追加一条显示消息，**不调用模型**。现有用法 `laolao-web-gpt-collab.js:877`。
  - 放手程度（P2）：`exec.approvals.get / set`，`agents.<agent>.security / ask`，缺省落到 `defaults`；三档见 `ui/injections/laolao-metre-perm.js:47-49`（auto = full/off，ask = allowlist/on-miss，off = deny/off），判档 `levelOf` 在 :51。
  - 允许清单（P3）：`ui/injections/laolao-metre-allow.js`，只改 `agents.metre.allowlist`；pattern 规则照原生 matchAllowlist / compileGlobRegex（不带路径按可执行文件名、带路径按完整路径；`*` 不跨文件夹、`**` 跨任意层；单个 `*` 放行全部）。
  - 插件侧：`api.registerGatewayMethod`（例 `services/mode-architecture/index.mjs:821` 起）；`metreLock.assertSessionAllowed(sessionKey)`；项目目录 `boundProjectRoot(sessionKey, {stateRoot})`（`project-brief.mjs:207`）；Windows 上已有 `powershell.exe -NoProfile` 的用法（`desk.mjs:205`）。
- **缺的**：一个插件里的「跑一条命令」网关方法、一个服务端保存的开关、界面上的识别和确认。

## 一、用户看到什么

1. **默认关**。碧琪设置弹层里多一张卡「聊天里用 ! 直接跑命令」（和 P3 的「允许的命令」卡一样走 `pinkie:settings-ready` 挂载），一个开关，下面一句说明：「打开后，以 ! 开头的消息不发给模型，直接在这个会话绑定的文件夹里跑；结果显示在对话里，下一轮模型也看得到。」
   - 关着时 `!ls` 照现在一样当普通消息发出去，行为不变。
2. **打开后**，输入框内容以半角 `!` 开头、后面紧跟非空白字符时，输入框左边出现小标签「命令」（composer 区域）。
   - 不算命令：`!!` 开头（原样去掉一个 `!` 当普通消息发，用来发真的感叹号开头的话）、`! ` 后面是空格、全角 `！`。
3. **按发送**：
   - 能直接跑（见第二节）→ 对话里立刻出一条「命令」消息：`$ <命令>`，跑完补上输出、「退出码 N · X 秒」。
   - 要先问 → 弹确认框：标题「跑这条命令？」，正文是命令原文 + 文件夹路径，两个键「跑」「算了」，默认焦点在「算了」，Esc 等于「算了」；底下一个勾「以后这个程序都直接跑」（勾上 = 把可执行文件名加进 P3 允许清单，只在 metre 这类有清单的代理上出现）。
   - 不能跑 → 输入框上方一句提示，命令留在输入框里，不发给模型：
     - 「这个代理设成了不跑命令」（P2 = 不跑命令）；
     - 「先给这个会话绑一个文件夹」（没绑项目文件夹）；
     - 「正在回答，先停下再跑命令」（这一轮还在跑）；
     - 分身会话照旧「分身会话只读」。
4. **在跑时**：停止键照常可用，按了就结束这条命令（连带子进程），消息里写「已停止」。超时（默认 120 秒）同样处理，写「超过 120 秒，已停止」。

不做：交互式命令（`vim`、`top`、要输入密码的 `sudo`）——没有标准输入，会等到超时；`cd` 不跨条保留（每条都是新进程，从绑定文件夹开始）。这两点属于 21（R2 每个会话一个终端），本项不等它、也不替它做。

## 二、走不走审批

结论：**走，和模型调用 exec 用同一套档位和清单**。`!` 是用户自己敲的，但同一个会话里模型下一轮能看到输出，页面上的脚本也能伪造发送；所以不因为「是用户敲的」就放宽，也不另起一套规则。

| 这个代理的档位（`agents.<agent>` 缺省落 `defaults`） | `!` 命令 |
|---|---|
| security `deny`（P2「不跑命令」） | 拒绝 |
| security `full`，ask `off`（P2「自动」，默认） | 直接跑 |
| security `allowlist`，ask `on-miss`（P2「问我」） | 在允许清单里 → 直接跑；不在 → 弹确认框 |
| ask `always` 或认不出的组合（P2 显示「自定义」） | 每次弹确认框 |

- **判定在服务端做**，界面只负责弹框：`pinkie.shell.run` 自己读 approvals、自己匹配清单，不信界面传来的「已放行」。界面确认后带 `confirmed: true` 再调一次；服务端只在「本来就该问」的档位上接受 `confirmed`，`deny` 档带了也拒绝。
- **不走原生审批弹窗**：裁剪 dist 里找不到 `exec.approval.request`，插件能不能主动发起原生审批（触发 `exec.approval.requested` 事件、由 `exec.approval.resolve` 回）本机核对不了。先用碧琪自己的确认框；若 linux2 核对后确认插件能发起原生审批，改走原生，界面改动更小（P2 已经在听这两个事件）。
- **清单匹配**：按 P3 写下的规则实现一个纯函数（取第一个可执行文件名或路径去匹配）。管道、`&&`、`;` 连起来的命令，**每一段的可执行文件都要在清单里**才算命中，否则按「不在清单」处理。完整的原生 matchAllowlist 语义（含 argPattern、shell 内建命令、别名）本机看不到源码，待 linux2 对着 openclaw 源码核对后对齐。

## 三、默认关，开关存哪

- 存在碧琪状态目录 `shell.json`（和 `boundProjectRoot(…, {stateRoot: pinkieStateRoot()})` 同一个 stateRoot），`{"enabled": false}`，文件 0600。不进 `~/.openclaw`、不进项目文件夹。
- 网关方法：`pinkie.shell.config.get`（scope `operator.read`）、`pinkie.shell.config.set`（scope `operator.admin`）。
- `pinkie.shell.run` 每次都先读开关：关着就回 `INVALID_REQUEST`，不管界面怎么调。
- 只有一个全局开关，不按代理分；按代理收紧靠第二节的档位。

## 四、执行细节和 Windows / macOS 差异

`pinkie.shell.run({sessionKey, command, confirmed?})`，scope `operator.admin`：

1. `metreLock.assertSessionAllowed`；`:subagent:` 和只读角色会话拒绝；会话这一轮在跑就拒绝。
2. cwd = `boundProjectRoot(sessionKey)`，没绑就拒绝（不退回家目录）。
3. 判档（第二节）。
4. 用 `spawn(file, argv)` 起进程，**命令原文只作为一个参数传给 shell**，不拼进别的字符串：

| | macOS | Windows |
|---|---|---|
| shell | `/bin/zsh -l -c <命令>`（登录 shell，PATH 和终端里一致，Homebrew 能用） | `powershell.exe -NoProfile -NonInteractive -EncodedCommand <base64>`（UTF-16LE 编码，省掉引号转义；前面加一句把输出编码设成 UTF-8） |
| 为什么不用另一个 | bash 在新系统上是 3.2，和用户终端不一致 | cmd.exe 的引号和编码坑更多；和 `desk.mjs:205` 保持一致。`irm …` 之类本来就是 PowerShell 写法 |
| 停止 / 超时 | `detached: true`，`process.kill(-pid, 'SIGTERM')`，2 秒后 `SIGKILL` 整个进程组 | `taskkill /T /F /PID <pid>`（连子进程） |
| 路径 | `/` | 绑定路径原样传，PowerShell 里 `/` `\` 都认 |

5. 环境变量：继承网关进程的环境，但**去掉名字里带 `KEY` / `TOKEN` / `SECRET` / `PASSWORD` / `CREDENTIAL` 的**（不分大小写），避免 `!env` 把网关的密钥打进对话、再进模型上下文。
6. 输出：stdout / stderr 合并，按到达顺序；对话里最多留 16 KB（超了留开头 4 KB + 结尾 12 KB，中间写「省略 N KB」）；去掉 ANSI 颜色码。
7. 结果用 `chat.inject`（label「命令」）写进对话：开始时一条 `$ <命令>`，结束时一条完整结果（不做流式更新，避免一条命令写几十条记录）。
8. 停止：`laolao-sidebar.js` 的 `chat.abort` 分支已经先发 `pinkie.watchdog.cancel`；`!` 命令在跑时界面另发 `pinkie.shell.cancel({sessionKey})`。
