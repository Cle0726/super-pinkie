## 一、用户看到什么

1. **每一轮回答的气泡上**（和「从这里分出去」同一排、同一个选择器 `.chat-group.assistant .chat-bubble[data-message-id]`），这一轮跑完、而且这一轮（或之后）动过文件时，多一个小键「回到这一轮之前」。
   - 放在回答气泡上而不是「你说的话」旁边：回答气泡已经有可靠的转录 id（`forkEntryId` 同一条取法），用户气泡没有；后台从这条回答往上找到发起这一轮的那句「你说的话」（见第三节），不靠 DOM 序号猜。
   - 还在跑时键是灰的，旁边写「先停下再回退」，按了不动（`aria-disabled`，`tabIndex = -1`，和 #161 一样不进 Tab 序列）。
   - 子会话（`:subagent:`）、只读角色会话不画键。这一轮的检查点已被上限清掉（第二节）也不画。
2. **点了先弹确认**，不直接动手：
   - 标题「回到第 N 轮之前」，正文「第 N 轮和之后的对话会撤掉；这几轮里改过的文件会还原。」
   - 下面三组文件：
     - **会还原**：路径 + 「改回原样 / 删掉（这几轮新建的）/ 重新放回（这几轮删掉的）」；
     - **之后被别处改过**（冲突，见第三节）：默认不勾，勾上才覆盖；
     - **还原不了**：太大没存、在项目文件夹外面、命令行改的但事先没认出来。只列出来，不动它们。
   - 某一轮命令行改动超过 1500 个文件、或碰了跳过目录，确认框多一句「第 K 轮用命令改过的文件可能没有全列出来」（审计器的局限，不瞒）。
   - 两个键：「回到这一轮之前」「算了」。默认焦点在「算了」，Esc 等于「算了」。
3. **确认后**：先还原文件，文件都成功了再撤对话；对话区重新拉一次记录；输入框里放回第 N 轮你说的那句话（方便改了重发）；右上角提示「已回到第 N 轮之前，还原了 K 个文件」。
4. **失败时**（文件被别的程序锁着、磁盘满、会话正被写）：提示一句人话，**文件和对话都保持回退前的样子**（已经写回去的文件用回退前备份再拨回来）。

不做：重做（回退之后再「前进」）、从某一步分叉并带上文件（「从这里分出去」照旧只带对话）、Metre 引擎台（外部引擎的文件不走网关的工具调用，钩子看不到，要的话另开一项）。

## 二、文件快照存哪、存什么

**存哪**：`pinkieStateRoot()` 下 `checkpoints/<sessionId>/`（不进项目文件夹、不进 `~/.openclaw`），权限 0700 / 文件 0600。

```
checkpoints/<sessionId>/
  index.json                 # 每一轮：{turn, userEntryId, startedAt, endedAt, files:[…], auditIncomplete}
  blobs/<sha256>             # 文件原样，按内容去重
  before-restore/<时间戳>/   # 回退前把当前内容先备一份，24 小时后清
```

`userEntryId` 是发起这一轮那句「你说的话」的转录 id，在这一轮第一次 `before_tool_call` 时从会话记录里取（当前分支上最后一条 user 消息）。

**范围**：绑定的项目文件夹（`boundProjectRoot` 回 `''` 就没有这一项，空串不当家目录）+ 这个会话的工作区。两者都没有就不记检查点、不画键。

**只记本轮改过的文件**，不拍整个文件夹。新钩子单独挂，不并进 :595 那个：

- `before_tool_call`，工具名在写入名单里（`write` / `edit` / `apply_patch` / `code_edit` 以及 `after_tool_call` 名单 `index.mjs:1221` 里的写入类）：用 `toolTargetPaths()` 取路径；**这一轮里第一次碰到**某个文件时，把它当前内容存成 blob，记 `{path, existed, preHash}`（不存在就记 `existed: false`，回退时删掉）。同一轮里再改同一文件不再存。
- `exec`、`run_tests`，以及写入名单里 `toolTargetPaths()` **一个路径也取不出来**的调用（例如参数里没有路径键的 `code_edit`）：
  - 能取出路径的先照上面存原样；
  - 再在同一进程里开一个 `RoleMutationAuditor`：`before_tool_call` 里 `beforeExec`，按 `toolCallId` 存着，`after_tool_call` 里同一个实例 `afterExec`。找出「变了但事先没认出来」的文件，记成 `{path, unrecoverable: 'exec'}`，**说实话列进「还原不了」**，不假装能还原。
  - 碰到 1500 个文件上限或跳过目录，这一轮记 `auditIncomplete: true`（第一节那句提示）。
  - 这是新挂的钩子，不改 `index.mjs:1191` 只读角色卡那段现成调用。
- `after_tool_call` / `agent_end`：给每个文件记本轮结束时的 `postHash`（冲突判断用）。
- 范围外的、符号链接、`.git` / `node_modules` 里的只记路径不存内容，列进「还原不了」。

**大小上限**（先定这几个数，写进常量，测试里覆盖）：

| 项 | 上限 | 超了怎么办 |
|---|---|---|
| 单个文件 | 2 MB | 不存内容，记 `unrecoverable: 'too-large'` |
| 一轮合计 | 20 MB | 这一轮后面的文件同上 |
| 一个会话合计 | 100 MB，且最多留最近 30 轮 | 从最老的一轮删起；被删掉的那几轮的键不再画 |
| 全部会话合计 | 1 GB | 按最后使用时间删整个会话的检查点 |

会话删除 / 归档时一起删它的 `checkpoints/<sessionId>/`。

## 三、回退时冲突怎么办

界面传 `{sessionKey, assistantEntryId}`（回答气泡的转录 id）。后台在当前记录里从这条往上走，找到最近的 user 消息，就是第 N 轮的 `userEntryId`；和 `index.json` 对不上就拒绝（「这一轮的检查点已经不在了」）。

回到第 N 轮之前 = 对第 N 轮及以后碰过的每个文件，取**最早那一轮**存的原样写回去。

- **冲突**：文件现在的哈希 ≠ 最后一次碰它那一轮记的 `postHash`，说明之后被人或别的程序改过。确认框里单列，默认不勾、不覆盖；勾了才覆盖。
- **写回去的做法**：先把所有要动的文件的当前内容备到 `before-restore/`，再逐个「写临时文件 → rename」。任何一个失败，就用 `before-restore/` 全部拨回来，报错，对话不动。
- **对话**（新模块自己做，不调 `trimChildFork`，也不改 `session-lineage.mjs`）：
  1. `parentRunning` 为真就拒绝（插件自己的信号；网关侧 `isEmbeddedAgentRunActive` 插件拿不到，不用）。
  2. `acquireSessionWriteLock({sessionFile, timeoutMs: 1000})`，拿不到就失败。
  3. 记下记录文件的大小和 mtime。
  4. `const sm = SessionManager.open(transcript)`（`createBranchedSession` 是**实例方法**，`src/agents/sessions/session-manager.ts:2866`），确认 `sm.getBranch()` 里有 `userEntryId`。
  5. **传 `userEntryId` 的 parentId**，不传 `userEntryId` 本身：叶子会被包含在路径里（`collectBranchedSessionPath`，:2776 起），传 user 消息 id 会把这句留下。第 1 轮（parentId 为空）就只留文件头。
  6. `createBranchedSession(parentId)` → `rewriteFile()`。路径里没有助手消息时 `rewriteFile()` 会延后（:2926-2933），文件可能还没写出来；这种情况由新模块自己按文件头 + 路径条目写出，不等它。
  7. 照 `trimChildFork` 那套抄一份换头（:469-473）：分支文件的第一行改回原记录的 header（保留原 session id），写临时文件 → rename 盖到**当前正在用的**记录上。rename 前再比一次第 3 步的大小和 mtime，变了就放弃（网关在锁外写了），连文件一起拨回。
  8. 对话这步失败，同样用 `before-restore/` 把文件拨回来——保证「要么都回去，要么都不动」。
  9. 截完把 `index.json` 里第 N 轮及以后删掉，界面重新拉记录。
- 换头那段要抄 `trimChildFork` 的写法，是因为 `session-lineage.mjs`（1894 行，只许变小）这次不动；以后它变小时可以把两处合成一个导出函数，不算本项。

## 四、要不要内核

**不要。** 全部在碧琪插件里做：
- 文件快照用插件已经能挂的 `before_tool_call` / `after_tool_call` / `agent_end` 钩子；

不改网关内核、不写 `patch/apply-*.mjs`、不用刷新 `desktop/windows/mac-runtime/`，cle-core 不用动。

局限（写进 PR，不瞒）：
- 只有经过网关工具调用的改动能还原；命令行里没认出来的写入、用户自己在编辑器里改的、引擎台外部引擎改的，都只能列进「还原不了」或「冲突」。
- 命令行改动超过审计器 1500 个文件或落在跳过目录里的，连路径都列不全，只给一句提示。
- 截的是正在用的记录：有写锁和 rename 前的比对兜着，但网关若在锁外写，结果是这次回退失败（文件也拨回），不会写坏记录。
