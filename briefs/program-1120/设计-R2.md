> 计划 program-1120 第 21 项。作者 macdev5，基于 main@b1dbc67c 与钉住的内核 2026.7.1-2（`desktop/windows/runtime-manifest.json`）。

## 〇 现在有什么、缺什么

**界面（`ui/injections/laolao-workbench.js`，2352 行，已超长）**
- 终端组件复用应用自带的终端面板（ghostty），`terminalClient.request` 包一层 `gwRequest`。
- `terminal.open` 成功后，若 `result.cwd !== state.root`，就发 `terminal.input`：` cd <root> && clear\r`（不加引号，路径带空格就坏）。
- `TERM_KEY = 'openclaw.terminal.sessions.v1'`（sessionStorage）；`parkTerminal(oldRoot)` 按**项目文件夹**把在线终端 id 存到 `store 'term.'+root`，切项目时换掉。
- 上下文：`terminalContext` Map（最多 12 条），按 sessionKey + root 过滤，上报给模型最多 3 个终端、每个 6000 字符。切会话时同一 root 的终端会把 key 改到新会话上（约 :468-471）。
- 结论：现在是「**一个项目文件夹一组终端**」。同一文件夹下的两个会话共用终端，A 会话里敲的输出会算进 B 会话的上下文。

**服务端（`services/mode-architecture/workbench.mjs`，884 行）**
- `snapshot` 返回 `terminal: {enabled: config.gateway?.terminal?.enabled === true}`；`publishContext` 收 terminals 时 `slice(0,3)`、output 截 6000。

**内核原生终端（2026.7.1-2）**
- 七个方法：`terminal.open / input / resize / close / attach / list / text`，全部要求已认证连接的 `connId`。
- `terminal.open` 先过 `resolveTerminalLaunchPolicy(agentId)`：disabled、unknown-agent、sandboxed（`sandbox.mode === "all"`）三种直接拒，配置延迟重启期间也 fail-closed。
- cwd 固定为 agent 工作区（不存在退 HOME），**客户端不能指定 cwd**。
- 上限：`DEFAULT_MAX_SESSIONS = 24`、断开后最多留 8 个、宽限 300 秒，到期 reaper 回收；超限报 `terminal session limit reached (N)`。
- `buildTerminalEnv` 把 `process.env` **整份透传**，只加 `TERM=xterm-256color`、`OPENCLAW_TERMINAL=1`。
- **没有 sessionKey（聊天会话）的概念**，终端只按 agent + 连接归属；**没有审批**，只有 enabled 开关和沙箱判断。

**缺的**：会话 ↔ 终端一一对应；cd 的引号；上下文只算本会话；环境变量里的密钥。

## 一 用户看到什么

- 入口不变：工作台的终端面板。行为改成「**每个聊天会话一个终端**」：
  - 第一次在某会话里打开终端 → 新开一个，cwd 进到这个会话的项目文件夹。
  - 切到别的会话 → 当前终端停放（不关），面板换成目标会话自己的终端；目标会话还没有就显示「打开终端」按钮，不自动开。
  - 切回来 → 接回原来那个（`terminal.attach`），滚动内容还在。
  - 删除 / 归档会话 → 关掉它的终端。
- 面板标题写「本会话终端 · <文件夹名>」，不出现内核产品名。
- 停放太多：一个窗口最多同时挂 8 个会话终端（原生总上限 24，留余量给其他窗口），超出时关掉最久没看的那个**空闲**终端，并在面板上提示一行「已关闭 <会话名> 的终端（最久未用）」。全都在跑时不关，直接提示「终端开太多了，先关一个」。
- 原生报 `terminal session limit reached` 时同样落到这句提示，不弹框。
- 没开启时沿用现有提示文案（gateway.terminal.enabled + 只在这台电脑的窗口出现）。沙箱模式下提示「当前会话在沙箱里运行，终端不可用」。

## 二 走不走审批（P2 放手程度 / P3 允许清单）

**定下：人手敲的终端不走 P2 / P3；R2 不给模型往终端里输入的能力。**

理由：
1. 终端是按键流，不是命令。一条输入可能是交互程序里的字、heredoc 的一行、`vim` 里的按键，没法像 I6 那样按 `|` / `&&` / `;` 切段去对清单，硬套只会误拦或漏拦。
2. 人自己敲的命令，本来就等同于他在系统终端里敲，再加审批是重复确认。
3. 模型要跑命令，走 I6 的 `pinkie.shell.run`（服务端判定、`confirmed: true`、清单逐段命中、120 秒超时、16 KB 留存）。以后如果真要让模型「在终端里打字」，也必须转成 `pinkie.shell.run` 那条路，不直接调 `terminal.input`。这一条写进代码注释和测试（见六）。

唯一的闸门仍是 `gateway.terminal.enabled` + 原生沙箱判断，界面不另造开关。

## 三 默认关，开关存哪

- 沿用 `gateway.terminal.enabled`（网关配置，默认 false），不新增开关，不新增存储文件。
- 「每个会话一个终端」直接替换现在「每个文件夹一组」的行为，不留两条路、不加功能旗。
- 会话 → 终端 id 的对应表放在界面侧 sessionStorage，新 key `pinkie.terminal.bySession.v1`（旧 `TERM_KEY` 读一次后丢弃）。
  - 理由（二选一：界面侧 vs 服务端存）：原生 `terminal.list` 本来就是哪些终端还活着的唯一事实来源，服务端再记一份只会和 reaper 打架；界面侧每次恢复先用 `terminal.list` 对一遍，不在的就删掉。窗口关掉 300 秒后终端被回收，对应表也随 sessionStorage 消失，两边一致。

## 四 执行细节和 Windows / macOS 差异

**进项目文件夹**：原生不让客户端指定 cwd，仍靠开终端后输入一行 cd，但必须按 shell 加引号：

| shell | 怎么判断 | 发送内容 |
|---|---|---|
| POSIX（macOS 默认 `$SHELL -l`，兜底 `/bin/bash -l`） | `result.shell` 不是 cmd / powershell | `cd -- '<root 里的 \' 换成 '\\''>' && clear\r` |
| cmd.exe（Windows 默认 `ComSpec`） | `result.shell` 末尾是 `cmd.exe` | `cd /d "<root>" && cls\r`；root 含 `%` 或 `"` 时不发，面板提示「路径含特殊字符，请手动 cd」 |
| PowerShell（`gateway.terminal.shell` 配了 pwsh / powershell） | `result.shell` 含 `pwsh` / `powershell` | `Set-Location -LiteralPath '<root 里的 ' 换成 ''>'; Clear-Host\r` |

- 判断看 `terminal.open` 返回的 `shell` 字段，不看界面所在平台（远端网关可能是另一台系统）。
- 换行统一 `\r`，ConPTY 和 POSIX pty 都认。

**环境变量**：原生整份透传 `process.env`，网关进程里的密钥会进终端；用户一敲 `env`，输出就进了 6000 字符的上下文，送给模型。处理：
- 打内核补丁 `patch/apply-terminal-env.mjs`：`buildTerminalEnv` 去掉名字含 KEY / TOKEN / SECRET / PASSWORD / CREDENTIAL（不分大小写）的变量，口径与 I6 一致。
- K5 切换前的规矩照办：改完在 Mac 跑 `tools/windows-package/refresh_mac_runtime.py`，`desktop/windows/mac-runtime/openclaw/dist/` 会多出 `launch-*.js`，Windows 包才生效。
- 双保险：上报上下文前，界面侧把输出里形如 `NAME=value` 且 NAME 命中上述词的行打码成 `NAME=***`。

**node-pty**：原生用 `@lydell/node-pty`（`1.2.0-beta.12`，dependencies）。
- macOS：正式包 `runtime/openclaw/node_modules/@lydell/` 里有 darwin / linux / win32-arm64 / win32-x64 预编译（只读看过）。
- Windows：`app/super_pinkie.py:167` 用 `npm install -g openclaw` 安装，没有 `--omit` / `--no-optional`，平台预编译包会按平台装上；`desktop/windows/mac-runtime/` 只是补丁差集，不影响依赖。**但没在 Windows 真机上验过 `terminal.open` 能起来**，列入七。

## 六 怎么测（都带反例）

- `tests/workbench-term-session-e2e.test.mjs`（WebKit 默认，`PINKIE_IMAGE_UI_ENGINE=chromium` 对照），假网关记录 `terminal.*` 调用：
  1. 同一文件夹两个会话 A / B：各开一个，拿到两个不同 sessionId；A → B → A 时对 A 调 `terminal.attach` 而不是 `open`。反例：退回按 root 存，第 1 步应红。
  2. 上下文：B 的上报里没有 A 的输出。反例：恢复 :468-471 改 key，应红。

  4. `terminal.list` 里没有的 id 恢复时被丢掉，面板显示「打开终端」。
  5. 模型侧没有任何路径调到 `terminal.input`（断言假网关只收到来自面板按键的 input）。

## 七 局限和待核对

1. **Windows 真机**：`npm install -g openclaw` 后 `@lydell/node-pty` win32-x64 预编译是否就位、ConPTY 能否起 `cmd.exe`。请 win 线在 Windows 上开 `gateway.terminal.enabled` 试一次 `terminal.open`。
2. 环境变量补丁是内核补丁，要不要做、做在 K5 前还是等 C.le. 内核里改，请 win-coord 定；不做的话只剩界面侧打码这一层。
3. 原生 cwd 不可指定，cd 是「开了再输入」，用户能看到一闪；cmd.exe 下含 `%` / `"` 的路径只能提示手动。
4. 对应表在 sessionStorage，换窗口（新窗口）不共享；同一会话在两个窗口各开一个终端是允许的，不做跨窗口互斥。
5. 300 秒宽限是原生常量，不改；窗口关掉超过 5 分钟，终端就没了，重新打开时是新终端。
6. 会话删除 / 归档的事件从哪取（是否已有统一回调）写代码前再核对，不新增观察器。
