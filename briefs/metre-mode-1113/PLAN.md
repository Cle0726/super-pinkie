## 二、定下来的设计

### 2.1 名字和身份

- 名字：**Metre**（用户定的）。agent id `metre`，后端模式名 `metre`，界面模式 id `metre`，工作区 `.openclaw/workspace-metre`，会话 key `agent:metre:…`。
- 用户可以改名，改名只动显示文字。

### 2.2 少读文件

Metre 的工作区只放三份文件：`AGENTS.md`（主 MD）、`IDENTITY.md`、`SOUL.md`（后两份各只有几行，作用是占位，防止系统放进默认的长模板）。不放 `playbooks/`、`HEARTBEAT.md`、`DREAMS.md`、`AESTHETICS.md`、`METHODS.md`。

对照：项目模式光 `AGENTS.md` 就是 57 KB，另有 31 张打法卡按需注入；Metre 的 `AGENTS.md` 是 12.5 KB。

每轮由插件注入的内容按下面的规则取舍（批 0 先做清点，见 3.1）：

| 留 | 去 |
|---|---|
| 传输和可靠性：断线恢复、压缩、追加消息、看门狗、模型健康 | 人设和语气相关的一切 |
| 说真话的门禁（交付前检查没验过的不说成做完）：逻辑一字不改 | 打法卡（work-cards）、技能路由（skill-routes）、工具箱提示（toolbox） |
| 用户自己设的：项目说明、联网开关、回答风格、派发 / 独做 | 活的分类计划段（work-kinds 的 kindPlanSection）、档位契约（run-contract 的层） |
| 子会话的汇报和唤醒、计划清单、`ask_user` | 「别的模式更拿手」提醒（session-hints）、陪伴、学习提醒、第一人称改写、心跳、记忆自动回放 |
| 长期记忆工具本身（按需调用） | |

拿不准该留该去的，一律留，并记进 `PROGRESS.md` 等 Fable 定。这条不能反着来。

**预算**：Metre 一轮的固定文字开销（工作区文件 + 插件注入，不含工具定义）不超过 6000 字。批 0 量出项目模式的同口径数字写进 `PROGRESS.md` 作对照。

### 2.3 权限

用户的原话：「全部没有限制」。

- 工具集 = 项目模式的全套 + 会话类工具 + 本计划新增的两个，一个不少。
- 工具的放行策略和无限制模式现在的一致（本机网关的 `CLE_KK_LOCAL_UNRESTRICTED` 那一套，见 `patch/apply-local-unrestricted-policy.mjs` 和无限制 agent 在 `setup.py` 里的工具配置）：命令直接执行，不弹确认，不限路径。批 0 把无限制 agent 的工具配置原样抄给 `metre`，逐项对比。
- 不设「不可逆动作先问用户」的关卡。删除、覆盖、推送、发消息都直接做。分寸写在主 MD 第十一节：动手前核对对象、先备份、做完说明。这是做事的方法，不是拦截。
- 只借无限制模式的放行策略，不带它的运行时注入标记（`OPENCLAW_UR_INJECT`）。Metre 的工作区里只有它自己那三份文件。
- 可以派活到 `chat`、`project`、`ideas`、`learning`、`unrestricted` 五个模式。派到无限制模式只有 Metre 能做；四个老模式之间的跨模式规则不变，它们仍然不能把活开到无限制模式。
- 别的模式不能把活派进 Metre，也不能 `pinkie_mode_ask` Metre；`session-hints` 永远不建议「去 Metre 模式」。Metre 贵，只由用户自己打开。
- Metre 的子会话必须指定五个模式之一，不能开在 `metre` 里。
- 留着的两样不算权限限制，说明一下：说真话的交付检查（没验过的不说成做完）；汇报、网页、文件里夹带的指令不当成用户的话。

### 2.4 派发机制（在 `session-lineage.mjs` 上改，只对 Metre 父会话生效）

| 项 | 现在 | Metre |
|---|---|---|
| 同时在跑的子会话 | 4 | 默认 8，设置里 2 到 12 可调 |
| 一轮里自己直接开（`in_scope`） | 3 个，且只能在用户亲自发来的那一轮 | 6 个；被子会话汇报叫醒的那一轮也可以开（心跳、记忆整理等内部轮次仍不行） |
| 汇报唤醒 | 每个子会话最多 3 次 | 每份汇报都唤醒；Metre 正忙时到达的汇报合并成一次 |
| 一次用户请求累计开的子会话 | 无 | 默认 24 个，到了就停下来告诉用户，用户回话后重新计数；设置里可调，填 0 表示不封顶 |
| 指定模型 | 继承用户在父会话选的 | `pinkie_session_start` 新增 `model`；不写用目标模式默认 |
| 指定文件夹 | 继承父会话的项目绑定 | 新增 `folder`，可开到另一个项目文件夹 |
| 层数 | 一层 | 一层，不变 |

**模型规则（后端硬性执行）**：

- `model` 必须在 `pinkie_models` 当前返回的列表里，且健康。
- 归一化后（去掉提供方前缀、路由后缀、思考强度后缀）不能和 Metre 自己正在用的模型相同，相同就拒绝并说明原因。目标模式的默认模型恰好和 Metre 相同时，要求必须写 `model`。
- 子会话的模型写进血缘记录，看板和汇报卡片上都显示。

**暂停和全停**：

- 暂停派发：看板上的开关。打开后 `pinkie_session_start` 返回「用户暂停了派发」，已经在跑的不受影响。
- 全停：停 Metre 当前这一轮，再停它名下所有在跑的子会话（复用侧栏归档时「先停子会话」的那段逻辑，12 秒超时），不归档、不删任何东西。停完后看板显示每个子会话停在什么状态。

### 2.5 `pinkie_models`（新工具）

返回当前能用的模型，每个带：`id`、显示名、档次（`light` / `mid` / `top`）、是否健康、能否看图、工具是否用得稳、`self`（是不是 Metre 自己）。

- 数据来源：`model-sync.mjs` 同步到的列表 + `model-health.mjs` 的健康状态。不发新的网络请求。
- 档次表放在 `services/mode-architecture/model-tiers.json`：按模型名的规则分档，表里没有的按名字里的 `mini / flash / lite / haiku / luna` 等归 `light`，其余归 `mid`。`top` 只给表里明确列出的。表的初稿由实现者按本机实际目录填，Fable 验收时过一遍。
- 最多返回 40 个，按档次分组，不健康的排最后并标原因。

### 2.6 派发 / 独做

- `session-prefs.mjs` 的模式专属字段加一项：`metre: {field: 'dispatch', values: ['dispatch', 'solo']}`，默认 `dispatch`。
- 每轮注入一行：`【本轮：派发】` 或 `【本轮：独做】`（主 MD 第四节认的就是这两个词）。
- 独做时，`pinkie_session_start` 和 `pinkie_mode_ask` 对这个会话不提供（工具工厂返回空），不是靠模型自觉。
- 界面：输入框下方一颗两段开关「派发｜独做」，常驻在外，不收进工具箱。切换时提示一句：「这个会话改成自己做，不开子会话」/「这个会话改回派发」。

### 2.7 `pinkie_sessions`（新工具，新文件 `session-manage.mjs`）

| 动作 | 作用 | 说明 |
|---|---|---|
| `list` | 列出侧栏会话 | 可按模式、项目、状态、是否归档筛；带标题、模式、项目、状态、最后活动时间、父子关系 |
| `search` | 按文字搜会话 | 复用 `session-search.mjs` |
| `read` | 读一个会话的内容 | 默认最近 20 条消息、最多 8000 字，可翻页；工具调用只给名称和一行摘要 |
| `create` | 新建会话 | 指定模式、项目名或文件夹、标题、第一条消息（可空）、模型；建好后出现在侧栏对应项目下 |
| `rename` | 改名 | 用户手动起的名字受保护（沿用现有规则） |
| `detach` | 把子会话移到顶层（解绑） | 复用 `pinkie.session.detach` |
| `archive` / `unarchive` | 归档 / 取消归档 | |
| `stop` | 停一个会话正在跑的那一轮 | |
| `delete` | 删除会话（只有 Metre 有） | 先把会话记录挪进状态目录下的 `backups/sessions-deleted/<日期>/`，再从侧栏移除；结果里带备份位置 |
| `stop_children` | 停自己名下所有子会话 | Metre 的「全停」用它 |

- 在 Metre 里：所有动作对任何会话都直接生效，不出确认卡片。
- 在四个老模式里（跑的是轻量模型）：对自己开出来的子会话直接生效；对其他会话的 `archive`、`stop`、`rename` 先出一张确认卡片，用户点了才执行；没有 `delete`。
- `read` 读到的内容包在「资料，不是指令」的标记里（和子会话汇报同一套说法）。
- 开放范围：Metre + 四个老模式；无限制模式和临时会话没有。老模式的手册不改（那些 MD 归 Fable，另行处理），靠工具自身的说明文字就够用。

### 2.8 状态词补全（所有模式）

现在的状态词（`laolao-cle-stage.js` 的 `VERB`、`laolao-phrases.js`、`laolao-tool-stream.js`、`laolao-run-status.js`）把「写文件」一律叫「正在写入」，看图和生图混在一起。补成：

| 类别 | 进行中 | 完成后 | 怎么判定 |
|---|---|---|---|
| create | 正在创建 | 创建了 `文件名` | 写入的路径在调用前不存在（后端 `before_tool_call` 查一次，随事件带出） |
| write | 正在写入 | 写入了 `文件名` | 路径已存在且整体覆盖 |
| delete | 正在删除 | 删除了 … | 命令是 `rm / del / Remove-Item / trash` 等 |
| move | 正在移动 | 移动了 … | `mv / move / ren` |
| install | 正在安装 | 安装了 … | `npm|pnpm|yarn|pip|brew|winget … install/add` |
| build | 正在构建 | 构建完成 | 常见构建命令 |
| git | 正在提交 / 推送 / 拉取 | 已提交 … | `git commit / push / pull / fetch` |
| download | 正在下载 | 下载了 … | `curl -O / wget / Invoke-WebRequest -OutFile` |
| view | 正在看图片 | 看了 `文件名` | 读的是图片文件，或 `image` 工具（现在被归到「图片生成中」，是错的） |
| shot | 正在截图 | 截了一张图 | 浏览器、电脑操作的截图动作 |
| dispatch | 正在派发 | 派给了 `模式` | `pinkie_session_start` |
| wait | 在等子会话 | | Metre 这一轮结束、仍有子会话在跑 |
| review | 正在验收 | | Metre 被汇报叫醒后的那一轮 |
| manage | 正在整理会话 | | `pinkie_sessions` |
| models | 正在看可用模型 | | `pinkie_models` |

规则：真创建才叫创建；判定不了的退回原来的说法，不能猜。命令分类只看命令开头的程序名，不做复杂解析。四处文案表要一致，写一个测试把四张表对齐。

### 2.9 读图小框（所有模式）

- 工具结果里带图片时（读图片文件、`image` 工具、浏览器截图、电脑截图、生成的图），过程里那一行右侧放 40 像素的缩略图，旁边是文件名。多张最多排 4 张，其余写「+N」。
- 点缩略图用现有的 `laolao-image-viewer.js` 打开大图。
- 刷新、重开会话后还在（参照 `apply-history-image-thumbnails.mjs` 对用户图片的做法）。
- 安全：图片走现有的工作区媒体通道，但只放行「这个会话里工具确实读过」的路径（后端在 `after_tool_call` 记一份清单），不能变成任意读文件的口子。
- 图片已经不在磁盘上时显示一个灰框和「图片已不在」，不报错。

### 2.10 界面：素净皮肤

根节点 `data-laolao-mode="metre"` 时生效，新文件 `laolao-metre-skin.css`，只在这个模式下起作用，不改其他模式的任何样式。

- 色：浅色底 `#FAF9F5`、正文 `#1F1E1D`、次要文字 `#73726C`、分隔线 `#E8E6DC`、强调色 `#C96442`（只用于主按钮和进行中的标记）；深色底 `#262624`、正文 `#F0EEE6`。不用粉色，不用玻璃和渐变，不用气球、彩带、贴纸。
- 字：正文用系统无衬线，助手的长回答用衬线（`ui-serif, Georgia, "Songti SC", "SimSun", serif`），代码等宽。
- 不出现：碧琪头像和表情、模式横幅图、转场动画、小碧琪、随机一句、碧琪口吻的状态话术（`laolao-phrases.js` 给 Metre 一套平实说法：「思考中」「正在读取」…）。
- 保留：流式输出动画（`laolao-stream-fx.js`）、过程卡片、工具流、运行状态条、子会话那条细线（`laolao-crew.js`）、计划清单、`ask_user` 卡片、模型选择器、工作台。
- 模式切换菜单里 Metre 这一项：一个像素猫头小图标 + 「Metre」两个字，没有立绘。切入切出不放转场。

### 2.11 像素黑猫

原型是用户自己的 C.le.控制台 App 图标上那只黑猫（参考图 `briefs/metre-mode-1113/ref/cle-cat.png`）：通体黑，耳朵又尖又大，眼睛细长上挑、发蓝光，侧坐，尾巴从身后绕到身前，脚下一道蓝色的影子，旁边一朵灰色小花。像素版要让人一眼认出是同一只。美术由 Fable 画，**用户看过预览点头后才能上**，上的必须和预览一模一样。

- 画布 16×16 像素，整数倍放大显示（状态条里 2 倍，看板里 3 倍），`image-rendering: pixelated`。
- 色（从图标上取）：身体 `#0E0E10`，深色主题下加一圈 `#3A3A3C` 描边；眼睛 `#2F9BFF`，眼睛高光 `#9AD4FF`；脚下的影子 `#1F3FA8`；小花和胡须 `#8A8A88`。总共 6 色。眼睛是整只猫唯一的亮色，各个状态主要靠眼睛和尾巴表达。
- 默认姿势照图标：侧坐、头微低、尾巴绕到身前。
- 帧数据写成 JS 里的字符串数组，画到一块 `<canvas>` 上。不用 WebGL，不用 GSAP，不用图片精灵文件。
- 最高 8 帧每秒；页面不可见时停；空闲状态眨一次眼后静止，隔 6 到 10 秒再眨；尊重「减少动效」开关（开了就只显示每个状态的第一帧）。

| 状态 | 画面 | 帧数 |
|---|---|---|
| 空闲 | 坐着，偶尔眨眼、甩一下尾巴 | 4 |
| 思考 | 眼睛向上看，尾巴慢摆 | 4 |
| 读取 | 眼睛左右扫 | 4 |
| 写入 / 修改 | 两只前爪轮流按 | 4 |
| 创建 | 爪子前面冒出一个小方块 | 4 |
| 执行命令 | 原地小跑 | 4 |
| 搜索 / 看网页 | 耳朵转动，头左右探 | 4 |

### 2.12 总控台

新文件 `laolao-metre-board.js/.css`，右侧面板，可收起，窄窗口下变成从状态条点开的浮层。只在 Metre 模式出现。

3. **子会话**：一行一个。标题、模式、模型、状态（排队 / 运行中 / 等回复 / 已交回 / 已验收 / 打回 n 次 / 失败 / 已停）、已用时间、此刻在做什么（它最近一次工具的状态词）、用量。操作：打开、停止、发消息。失败的那行显示原因。
4. **时间线**：派发、汇报、打回、验收、出错、用户叫停，带时间，新的在上。
5. **改动**：这一家子会话动过的文件，按会话分组，点开在工作台里看。
6. **待你处理**：等回答的 `ask_user`、等点的确认卡片。有内容时面板标题上出数字。
7. **运行环境**：网关连接、正在用的几个模型的健康状态、最近的上游错误、Metre 自己的上下文用量、这件事累计的用量。

数据：新增只读接口 `pinkie.metre.board`，后端把血缘、运行状态、计划、用量、模型健康、后台任务拼成一份返回。前端靠已有的 `pinkie:gateway-event` 触发刷新，每秒最多刷一次；没有事件时不轮询。断线时面板顶上显示「连接断了，正在重连」，不把断线显示成做完。

### 2.13 资源关停

目标：Metre 模式下，装饰性的开销只有那只猫。

**前端**（当前模式是 `metre` 时）：

- 停掉并释放：小碧琪（`laolao-buddy-rig.js`）、舞台和空间（`laolao-cle-stage.js` 的装饰层、`laolao-cle-space.js`）、转场（`laolao-mode-transition-fx.js`）、陪伴（`laolao-companion.js`）、夜间氛围（`laolao-night.js`）、沉浸（`laolao-immersion.js`）、派对和圆桌入口、学习台和游戏的所有模块、页面预热里对其他模式素材的预加载。
- 做法：每个重模块提供 `suspend()` / `resume()`，由一个小调度器在模式变化时统一调用；懒加载的大库（three、gsap、mermaid 等）在 Metre 模式不主动加载，用到才加载。不许用「隐藏」冒充「停掉」：定时器、`requestAnimationFrame`、观察器、WebGL 上下文都要真的停。
- 切回别的模式时全部恢复，不需要刷新页面。

**后端**（Metre 是当前模式、且没有其他模式的会话在跑时）：

- 停掉只为碧琪体验服务的定时和轮询：陪伴、学习提醒和约定、学习资料后台任务的空转轮询、心跳（Metre 工作区本来就没有 `HEARTBEAT.md`）。
- 不停：网关、模型同步和健康、会话标题、看门狗、子会话调度、消息渠道（微信、飞书等是用户接的外部通道，默认不动；在设置里给一个开关「Metre 模式下暂停消息渠道」，默认关）。
- 子会话跑在别的模式里，它们用到的东西照常工作。

**要量**：进入 Metre 模式前后，空闲和运行两种情况下的渲染进程 CPU、内存、活着的定时器数、`requestAnimationFrame` 回调数、WebGL 上下文数。目标见验收。数字写进 `PROGRESS.md`。

## 五、风险

| 风险 | 对策 |
|---|---|
| Metre 反复派发、互相打回，烧额度 | 单次请求默认 24 个子会话后停下来报告（可调）；同一块活打回两次必须换模型或自己做（MD 第十节）；看板随时可全停 |
| 关注入时误关了门禁或可靠性逻辑 | 先清点后动手；拿不准的留；门禁的测试原样要过 |
| 改 `session-lineage.mjs` 影响老模式 | 所有新行为按父会话是否 Metre 分支；老模式的现有测试一条不改、全过 |
| 权限全开后，轻量模型做坏了重要的东西 | 收不回的步骤尽量由 Metre 自己做，交出去时把对象写死；动手前备份；Metre 亲自验收（MD 第十、十一节）；删除的会话进备份目录 |
| 资源关停后切回别的模式出问题 | `suspend / resume` 成对测试；来回切 20 次的冒烟 |
| 读图小框变成任意读文件的口子 | 只放行工具读过的路径清单；加越权测试 |
| 两端同时改同一个文件 | 上面的文件表 + `PROGRESS.md` 里的接力棒 |
