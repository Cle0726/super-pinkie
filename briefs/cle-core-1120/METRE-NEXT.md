## 一、用户要什么

用户原话（11-22）：

- 「根据问题总是很多我建议以后先去找开源类似项目拿回来优化，避免自己写出来老是有问题」
- 「我感觉我很需要 T3 code 的功能（使用 Antigravity，GPT，Claude 这些等等）……但是我又想保留 Metre 一部分设计，对比之下别人项目的页面功能按键更加完善更加成熟，所以需要吸收回来换个 Metre 的 IP 就行」
- 「如果可以也把计划写进 Cle 内核计划，到时 Cle 计划完成可以自己复用，节省不必要的消耗；现在先做现在这个内核」
- 反复出现、最烦的问题：前后端不同步；漏补丁、漏插件；流式输出到后面不见；Metre 派发时突然跳到空的新会话、父会话记录不见；子会话单独一栏、不挂在父会话下；跳转没有动画衔接；后台命令跑完不唤醒 Metre；总谱内容重复、没有视觉语言、按键像假的、按键重叠。

拆成要做到的事：

| 编号 | 要做到 | 怎么算做到 |
|---|---|---|
| N1 | Metre 能把活派给用户自己登录的外部编码智能体：至少 Claude Code、Codex、Antigravity | 在 Metre 里派一件活给这三家各一次，子会话里看到它们的流式输出、工具调用和最终结果；用的是用户自己的订阅，碧琪不保存这些账号的凭据 |
| N2 | 界面状态只有一个来源：后端的事件流 | 同一个会话开两个窗口、断网重连、刷新页面，三种情况下两边显示逐条一致；没有任何一块界面靠读别的界面元素拼数据 |
| N3 | 派出去的子会话就挂在父会话下面看，不切模式、不丢父会话 | 在 Metre 里点开任何子会话（包括别的模式、外部智能体的），父会话一直在侧栏原位、记录完整；返回父会话不重新加载 |
| N4 | 页面和按键达到成熟产品的水平，但是 Metre 的样子 | 和 T3 Code 同一功能的画面并排对比，每个按键都有；外观是 Metre 自己的（像素 M 标志、月夜、黑猫、Baton/Virtuoso 等音乐用词），没有 T3 的名字、标志和配色 |
| N5 | 总谱每个按键都接后端，内容不重复 | 「按键契约测试」：每个按键 → 调用哪个接口 → 界面哪里变化，逐个自动测；同一个数字在总谱里只出现一次 |
| N6 | 以后其他模式也能复用 | 事件流和外部智能体桥做成内核的公共部件，不是 Metre 专用 |

**不做的事**：

- 不把 T3 Code 的页面用注入脚本塞进现在的控制台。今天的大部分毛病正是「注入脚本拼界面」造成的，再塞一个只会更乱。
- 不转卖模型额度，不代管用户在外部智能体上的登录。
- 不用 T3 的名字、标志、截图和配色。只借 MIT 许可的代码和做法，保留它的版权声明。
- 不改碧琪的五个老模式（唠嗑、项目、想法、学习、无限制）的界面和行为。`PLAN.md` H3「界面不能变」对这五个模式继续有效；**只有 Metre 的界面按本文改**（用户 11-22 的要求）。
- 不借 OpenManus（见第二节）。

## 二、评估（11-22 核对）

| 项目 | 是什么 | 许可 | 结论 |
|---|---|---|---|
| T3 Code `github.com/pingdotgg/t3code` | 编码智能体的统一控制台：一个本机服务驱动 Claude Code、Codex、Cursor、OpenCode、Grok、Antigravity、Kiro 和任何 ACP 智能体，桌面、网页、手机三端看同一批会话；每个会话可以有自己的工作树，带差异审阅、提交、开 PR | MIT（GitHub API 核对），TypeScript，约 7.2 万星，11-23 仍在更新 | **借**。它解决的正是我们反复出问题的那一层：会话状态放在服务端，所有客户端只按事件流画界面 |
| OpenManus `github.com/FoundationAgents/OpenManus` | Python 的通用智能体框架（浏览器、MCP 工具、实验性的多智能体流程），没有图形界面 | MIT | **不借**。它和 C.le. 内核是同一层的东西，碧琪这层已经更完整；它的多智能体流程官方标着不稳定。用户说的「Opanmaus bot」按这个项目理解；如果指的是别的项目，再单独评估 |

为什么老是出同一类毛病（11-22 查到的根子，不是猜的）：

1. **会话的名字和会话的记录是两回事。** OpenClaw 默认每天凌晨 4 点给会话换一份新记录，名字不变。界面只认名字，于是「突然变成空的新会话」。碧琪 11-22 在现内核上已经关掉（分支 `fix/metre-session-sync`），但根子是界面没有「记录换了」这个概念。
2. **叫醒链条每一环都可能悄悄放弃。** 后台命令跑完要经过：守望 → 判断忙不忙 → 命令行调网关 → 进入会话。任何一环失败都不留日志、不告诉用户。11-22 已经加了重试和日志，但同类链条（子会话回报、汇报卡片、看门狗续跑）还有好几条。
3. **一个模式就是一个智能体。** Metre 派到别的模式的子会话，住在别的智能体里；界面要看它只能切模式，切过去父会话自然就不在侧栏了。
4. **界面是 121 个注入脚本拼的**（维护计划 11-20 的测量），各自读别的元素、各自轮询。前后端对不上、流式输出到后面不见，大多出在这里。

T3 Code 的做法正好对着 1、3、4：服务端记一条带序号的事件流，客户端只按事件画，断线就按序号补；一个线程里可以换模型、换智能体；子任务就是线程里的一段，不需要「切模式」。

## 三、总体做法

1. **固定版本搬代码，不跟着它自动升级。** 在 `cle-core` 里用一个固定提交（K8-0 选定）引入 T3 Code 需要的部分，放在 `vendor/t3code/`，原样保留 LICENSE，另写 `NOTICE` 说明来源和改动。以后要它的新修复，按 `PLAN.md` 第七节「上游规矩」一样挑着合。
2. **内核里加两个公共部件**（N6）：
   - `thread-events`：每个会话一条带序号的事件流（消息、思考、工具调用、子会话开始/回报、后台命令、记录更换）。网关提供订阅和「从第 N 条补发」。会话记录要换（压缩、用户点新会话）时发一条事件，界面不再被蒙在鼓里。
   - `agents-bridge`：从 T3 Code 的服务端搬「驱动外部智能体」那一层，接成碧琪的一种子会话目标：`pinkie_session_start` 新增 `target: "external"` 和 `provider`（`claude-code`、`codex`、`antigravity`，以后再加）。外部智能体的输出转成上面的事件流。
3. **Metre 新前台** `apps/metre-web`：以 T3 Code 的网页端为底改写，换成 Metre 的样子。只连 `thread-events`，不读别的界面元素，不用注入脚本。和老界面并存，设置里一个开关切换（K8-5）。
4. **总谱重做成事件流的一个视图**：总谱上的每个数字、每条时间线都从同一条事件流算出来，不再另记一本账；每个按键都有契约测试（N5）。

## 四、分批

每批一个 PR，按 `briefs/program-1120/CONCURRENCY.md` 执行和合并。

### K8-0 · 摸底（只看，不改产品代码；K5 之前就可以做）

1. 浅克隆 T3 Code 到临时目录（不进任何仓库），记下选定的提交号。
2. 列清楚：服务端驱动外部智能体的模块、事件协议、网页端的会话/线程/差异审阅组件、它们各自的依赖和许可证（依赖里有 GPL/AGPL 的，那一块不能搬，写明换什么）。
3. 把它的事件协议和 OpenClaw 网关现有事件（`chat`、`agent`、`sessions.*`、碧琪的 `pinkie.*`）一一对照，写成 `briefs/cle-core-1120/T3-MAP.md`：哪些直接对应、哪些要新增、哪些不要。
4. 实测：在隔离环境装好 T3 Code，用 Claude Code、Codex、Antigravity 各跑一个小任务，录下事件流样本，存进 `T3-MAP.md` 的附录（去掉账号信息）。
5. 交出：`T3-MAP.md` + 一个结论：哪些代码搬、哪些照着写、哪些不要。

### K8-1 · 会话事件流（内核）

1. 在 `cle-core` 里实现 `thread-events`：带序号、可补发、记录更换和压缩也是事件。
2. 碧琪现在的 Metre 界面先改成读这条流里的「记录更换」和「后台命令」两类事件（解决「突然空白」「不叫醒」的根子），别的不动。
3. 测试：断线 30 秒重连后界面和服务端逐条一致；凌晨 4 点、压缩、用户点新会话三种换记录的情况，界面都给出说明而不是空白。

### K8-2 · 外部智能体桥（内核）

1. 从 T3 Code 搬驱动外部智能体的那一层，接成 `agents-bridge`，先做 Claude Code、Codex、Antigravity 三家。
2. Metre 派活时可以选外部智能体；模型/智能体的选择规则写进 Metre 手册和 `pinkie_models` 的返回（外部智能体标「用你自己的订阅」）。
3. 凭据：只检测本机有没有装好、有没有登录，不读、不存、不转发登录信息。没登录就在子会话里告诉用户去哪里登录。
4. 审批：外部智能体要执行命令、改文件时的审批，走碧琪现有的确认卡片；无限制模式规则不适用于外部智能体。
5. 测试：三家各派一件活；中途停止、重连、额度用完三种情况都要在 Metre 里正确显示。

### K8-3 · Metre 新前台

1. `apps/metre-web`：以 T3 Code 网页端为底，保留它的线程列表、子任务嵌套、差异审阅、审批、模型切换这些功能和按键。
2. 换成 Metre 的样子：沿用已经定下的像素 M 标志、月夜背景、黑猫、Baton/Virtuoso、谱纸配色（见 `briefs/metre-mode-1113/` 和 `docs/METRE-MODE.md`）。T3 的名字、标志、配色一处都不能留。
3. 子会话（别的模式的、外部智能体的）都在父会话里打开：侧栏嵌套 + 右侧分栏，不切模式；进出有过场动画。
4. 交界面活必须附「T3 Code 原版 / Metre 新版」并排对比图，逐项列出按键是否都在（用户 11-14 的要求：交界面必须附对比图，量过再交）。

### K8-4 · 总谱重做

1. 先写 `briefs/cle-core-1120/METRE-BOARD-SPEC.md`：总谱要回答的问题（谁在做、做到哪、等我什么、改了什么、出了什么错），每个问题只在一个地方回答；视觉语言（声部 = 一行、小节 = 时间、记号 = 状态）。
2. 数据全部来自 `thread-events`，删掉后端另记的那本小账（`metre-board/`）里和事件流重复的部分。
3. 按键契约测试：每个按键一条自动测试——点下去调用了哪个接口、后端状态变了什么、界面哪里变了。没接后端的按键不许出现；做不了的功能不放按键。
4. 数据没到时显示「正在读取」，不再画示例图（11-22 用户看到的「假按键、假内容」主要是这些示例图）。

### K8-5 · 切换

1. 设置里加「新版 Metre」开关，默认关；用户自己用 3 天以上没有新问题，再默认打开（要用户点头）。
2. 默认打开以后保留老界面两个正式版；之后删除老 Metre 的注入脚本和样式（和 K6 一起记账，棘轮基线同步变小）。

### K8-6 · 复用到其他模式（以后再说）

N6 的两个部件做好以后，其他模式要不要换前台，另立计划、用户点头。本计划不做。

## 五、开源优先的规矩（整个计划都适用，从现在起生效）

用户 11-22 的要求：以后先找成熟的开源项目，再决定自己写。执行者在开始任何**预计超过 300 行的新功能**之前：

1. 搜一遍有没有成熟的开源实现（看许可证、星数、最近更新、有没有正经的测试）。
2. 在接力卡里写清楚：找了哪些、为什么用或不用。
3. 只用 MIT、Apache-2.0、BSD 这类宽松许可证的代码；GPL/AGPL 的只能看做法，不能搬代码。保留原版权声明，在 `NOTICE` 里登记。
4. 搬进来的代码固定版本，不自动升级；改动集中在适配层，方便以后合它的修复。
5. 这一条不能当成「整块换掉」的借口：换底座、换界面框架这种大事，照样要单独立计划、用户点头。

## 七、11-22 已经在现内核上修的，和还没修的

现内核（OpenClaw）还要用很久，这些毛病不等 K8，按「现在先做现在这个内核」先修。已修的在分支 `fix/metre-session-sync`（基于 v2.5.54，尚未合并发版）：

| 问题 | 根子 | 状态 |
|---|---|---|
| 派发时突然跳成空的新会话、父会话记录不见 | OpenClaw 默认凌晨 4 点重置会话（实测 11-22 04:01，Metre 会话 f7306527 → 85ddaa66） | 已修：默认改成不自动重置，用户自己配过的不动 |
| 后台命令跑完不叫醒 Metre | 守望程序认为会话「忙」时无限等；叫醒失败 3 次（共约 9 秒）就悄悄放弃；Metre 要等所有子会话回齐才叫醒 | 已修：最多等 5 分钟、按 5 秒到 10 分钟递增重试、每一步写日志、Metre 不等子会话 |
| 总谱头部按键被窗口按钮压住 | 总谱贴右上角，Windows 的窗口按钮浮在同一位置 | 已修，并做了渲染前后对比 |
| 点子会话后父会话不见、子会话单独一栏、跳转没有过场 | 一个模式一个智能体，看子会话只能切模式（见第二节第 3 点） | 没修。现内核上的过渡办法：在别的模式里把来自 Metre 的子会话归到一个「来自 Metre：<父会话名>」的组下，组头可以一键回父会话，并补上过场。根治在 K8-3 |
| 等后台命令时一屏全是「思考了 X 秒」 | 免费小模型连续查后台进度，查询本身在界面里是隐藏的，只剩思考行 | 没修。办法：连续的等待调用合并成一行「在等后台命令（第 N 次查看）」 |
| 流式输出到后面不见 | 11-22 没有拿到能复现的会话 | 没修。下次出现时记下时间，按网关日志和会话记录查 |
| 总谱内容重复、没有视觉语言、像假按键 | 见 K8-4 | 头部按键实际已接后端；示例图和重复数字留给 K8-4 |
