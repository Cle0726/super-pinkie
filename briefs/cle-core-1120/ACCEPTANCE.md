# C.le. 内核接管 · 验收标准

对应 `PLAN.md`。验收方式（用户 2026-11-20 决定）：**每一批由执行者对照本文件自查**，逐条填写「过 / 没过 / 没测（原因）」，写进 `progress/<批号>.md`；**全部做完以后统一验收**，由别的 AI 按本文件逐条亲自核对，结果写进 `review/<批号>.md`。流程和报告格式见 `briefs/program-1120/ACCEPTANCE.md`。

## 统一验收时验收人的规矩

1. **只认证据**：命令输出、测试结果、截图和差异图、`git` 记录、发布包里的实际文件。`PROGRESS.md` 里写的「过」只当线索。
2. **必须亲自重跑的**：碧琪全量门禁、截图比对、注入对比，以及每批里带 ★ 的条目。
3. **判定**：带 ★ 的是必过项，任何一条没过，这一批就不过。不带 ★ 的，每批最多允许一条没过，而且要写明理由。「没测」不算过。
4. **`REVIEW.md` 怎么写**：每一条写结论、证据和复现命令；发现的问题另列一张表：严重程度、位置、复现步骤、建议。
5. 验收人只核对，不改代码。

## K2 · 碧琪支持两种内核

- **K2-1 ★** 碧琪的 Windows 打包、Mac 打包和安装脚本都只从 `core-manifest.json` 取内核：默认（`openclaw`）打出来的包，和 K2 之前的包里的内核文件逐文件一致；`PINKIE_CORE=cle` 打出来的包，内核来自 `cle-core` 的编译包。Mac 不再读取构建机上装着的 OpenClaw（贴出搜索命令和结果）。
- **K2-2 ★** 下载的内核包 sha256 和清单不一致时，打包和安装会停止并报错（做一个反例：改掉清单里的一位）。

- **K2-4 ★** 每个补丁在自编译内核上的执行结果，和在 npm 成品上一样（两份结果对照列出）。
- **K2-7 ★** 碧琪的 CI 里有「C.le. 内核」任务，每个 PR 都会跑；故意在一个临时 PR 里只弄坏 C.le. 那一路（例如把清单里 `cle` 的 sha256 改错一位），这个任务会失败，而 OpenClaw 那一路不受影响。临时 PR 用完关掉，不合并。
